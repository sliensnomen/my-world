schema → serve → run_tests → store 的顺序跑六套（先易后难，红了即停）→ 逐字节还原。

**假绿排除**：对 24 个全绿变异逐个做独立探针（不依赖测试库）——在同一个最小世界下，
未变异代码必须发射目标 finding，变异后必须消失或降级。24 个全部证实为真实缺口；

| 套件 | 抓到的变异数 | 备注 |

指错目录不给用法错误、CA201 豁免撤销、CA504 主体自列/排序反转、`world` 反向 legitimizes、
`exit 3`（关规则不显式授权）、econ CA602 上界与 justification——这些都被抓到，
说明「开关/聚合/报告」层的锁是合格的，缺口集中在**单条 finding 的直接断言**上。

## 6. 结论

**verdict: `needs_revision`**

六套全绿≠守卫都有锁：93 个变异里 24 个可以在测试全绿的状态下改坏，其中 **10 个直接把
门禁放行成 exit 0**（坏 status / 坏 layer / 坏 id / 坏 kind / 坏 figures / 坏 critical /
坏 note / 六个接线字段的形状错 / classlint 坏 id），另有 3 个让 `new`/`link` 子命令
静默产出坏数据或假成功。和上一轮相比，缺口不在「聚合与开关」，而在**每一条 finding 的
直接断言**——测试写了「世界级」的用例，没写「规则级」的用例。

修复顺序建议：

1. **P0（门禁静默变绿）**：N1–N10 各配一把规则级锁（最小世界 + 断言规则号 + 退出码），
   素材直接复用本报告 §1.1 的世界；
2. **P0（写入口）**：N11–N13 的 CLI 退出码 + 产物字节锁；
3. **P1（数据面/守卫面）**：N14–N23 的 finding/字段级锁，其中 N18/N19 并入上轮
   §1.2 已规划的两把锁（换正确病历）；
4. **P1（上轮遗留）**：H1 的 6 形状入锁 + 豁免谓词放宽到 `derives_legitimacy_from`。
