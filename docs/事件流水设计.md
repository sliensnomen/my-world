# 事件流水：设计决定（v0，2026-10-19）

> 这份文档只回答一件事：**世界怎么从「一堆静态卡片」变成「有历史的世界」**。
> 每条决定都写了「为什么」，因为下一个改它的人需要知道当时在防什么。
> 待定问题来自 [世界模型设计.md](世界模型设计.md) §12，本文把它们全部定下来。

## 0. 一句话

**卡片是账户，事件是流水，现在的状态是算出来的。**
作者可以不记账（只写结论），但一旦记了账，账就要能平。

## 1. 十个决定

### D1. 一笔账 = 一张 `type: event` 的卡

不另造文件格式，不另造 id 空间。

**为什么**：`type: event` 在契约里本来就是一等类型（示例世界里有 27 张），复用它能白拿
id 规则、`canon_refs`、去重（CA201）、`superseded_by`、快照与全部引用检查；
而「流水」这个说法要的只是**顺序**，顺序可以由字段给，不需要新的存储形态。

### D2. 事件字段（全部可选，只有「完整事件」才判）

| 字段 | 类型 | 含义 |
|---|---|---|
| `when` | 字符串 | 故事内时间，自由文本：`"第三纪 245 年"`、`"冰雨的风暴 第 3 章"` |
| `when_sort` | 数字 | 可选排序键，只用于比较先后；不给就不参与时序判定 |
| `event_kind` | 枚举 | 见下；给了它，这张卡就是「完整事件」，才进流水判定 |
| `by` | id 列表 | 施动者（谁做的） |
| `to` | id 列表 | 受方：转移的接手人，移动的目的地 |
| `object` | id 列表 | 客体：被转移、被移动、被造/被毁的那个东西 |
| `from` | id 列表 | 可选（协议 1.4）：移动的起点。先记后查——有了起点，「同一时刻出现在两个地方」这类轨迹矛盾才有得查 |
| `custody_of` | id 列表 | 可选（协议 1.4）：保管断言，写在保管人的卡上（与 owns 平行：owner 线与 keeper 线各有一套对账） |

`event_kind` 的取值（v0 六种，够了再加，`x-` 前缀可实验）：

| kind | 必填的腿 | 例子 |
|---|---|---|
| `transfer` | `by` `to` `object` | 铁王座把奔流城封给徒利家 |
| `custody` | `by` `to` `object` | 把剑交给侍从保管（所有权不变） |
| `move` | `object` `to`（`from` 可选） | 大军从凯岩城开往赫伦堡 |
| `create` | `object` | 筑城建港、锻造瓦雷利亚钢 |
| `destroy` | `object` | 焚城、断剑 |
| `grant` | `by` `to` `object` | 加冕、封爵、赐姓（名分转移） |
| `birth` / `death` | `object` | 出生、死亡（只有这两类可以凭空出现/消失） |

**为什么时间字段是自由文本 + 可选排序键**：世界观里的时间是「第三纪 245 年」「绿叉河之役前夜」，
规定死格式没人填；只给自由文本又排不了序。两个字段各干一件事，缺 `when_sort` 就 fail-open
（不做时序判定），比猜一个顺序诚实。

### D3. 期初状态 = 卡上的断言；变化 = 事件

- 卡上写的 `owns` / `controls` / `legitimizes` / `owes` 是**作者的断言**（无时间，等于「期初就这样」）；
- 事件是**变化**（有时间）；
- 派生状态 = 期初 + 流水算出来的结果。

**为什么**：这是 CIDOC CRM 的做法——「A 拥有 B」是 shortcut property，由「取得事件」推出；
手写的那条是结论，事件是过程。两者都允许存在，但**不许互相矛盾**（CA704）。

### D4. 流水不是一份文件，是一组卡

设计稿 §12.1 曾倾向「一个 `ledger.md` 放全部事件」。**否决**，理由是它违反
CBDB 的第一条设计律（一条事实只记一次）的配套要求：一笔账必须能被**单独引用**——
`canon_refs` 指得着、`superseded_by` 推翻得了、git 里能单独 diff、CA401 能查它的目标。
一个大文件里的事件块没有 id，这些全部要重造。

代价：事件多时目录里卡多。可以用 `entries/events/` 子目录缓解（`iter_entry_paths` 已递归）。

### D5. 期初那一层不单独存

期初就散在卡上（D3 的断言）。不另建「期初快照文件」——那会立刻和卡上字段重复，
且两份真值必然漂移。**理由**：这个仓库已经因为「两份实现」吃过一次大亏（见 PROTOCOL §9 第 18 条）。

### D6. 编号：流水族用 `CA7xx`

`CA6xx` 是 econ 扩展包（数值系统），流水是**核心**但不是每张卡都涉及，所以另开一族
`CA7xx`，与 CA1xx–CA5xx 并列，不重编号任何现有规则（编号即协议）。
`CA7xx` 只在世界里有「完整事件」时才可能有输出。

### D7. 规则表（v0 六条 + 协议 1.4 补 CA708–CA710）

| 编号 | 级别 | 名字 | 判什么 |
|---|---|---|---|
| CA701 | warning | 时序倒流 | 事件 A 的 `depends_on` 里有事件 B，且两者都有 `when_sort`：要求 `when_sort(B) ≤ when_sort(A)` |
| CA702 | error | 账不平 | 完整事件缺了本类必填的腿 |
| CA703 | warning | 无源之财 | `transfer`/`grant` 的客体在它之前没有任何持有者（既无 `owns` 断言，也无更早的 transfer/grant 指向它）。`create` 不算持有者来源：它的腿表只有 `object`，事件里没记「谁造的」，推不出持有者 |
| CA704 | error | 结论与流水打架 | 手写 `owns` 断言与「最后一条 transfer 推出的持有者」不一致。多值受方（`to` 多于一个 id）= 归属未定序：派生状态报告取第一个，CA704 对最终那笔受方列表里任一 id 的断言都放行；更早一笔的受方已被转手，不放行 |
| CA705 | warning | 死人做活事 | 事件的 `by` 里有人在更早的事件里已 `death` |
| CA706 | warning | 半截事件 | 声明了 `when` 或 `event_kind` 之一，另一个没给 |
| CA707 | warning | 断言互搏 | 同一客体被多张卡断言 `owns`，与有无流水无关（派生状态按 id 序取第一个只是给报告一个确定答案，不是裁决） |
| CA708 | warning | 不存在的东西在动弹（协议 1.4） | 客体的事件落在它自己的存在窗口外：`create`/`birth` 开窗、`death`/`destroy` 关窗；端点事件自身豁免。CA705 管 `by` 腿，本条管 `object` 腿 |
| CA709 | error | 保管对账打架（协议 1.4） | 手写 `custody_of` 断言与 custody 流水推出的最终保管人不一致（CA704 的保管版；custody 不改变持有者，只改保管） |
| CA710 | warning | 保管断言互搏（协议 1.4） | 同一客体被多张卡断言 `custody_of`（CA707 的保管版） |

**CA708 的隐含假设（记下，将来要破）**：客体的 id 在整个存在窗口内不变。`transform`（E81 式
转化：旧身份死、新身份生、物质延续）将来转正进词表时这个假设就被打破——届时转化事件本身
即窗口边界：前一个 id 的窗口止于它，后一个 id 的窗口始于它。加 `transform` 的那一轮必须
回来改这条规则，别把旧 id 的后续事件误报成「死后动弹」。

**为什么 CA704 是 error 而 CA703 是 warning**：前者是「同一件事有两个互相矛盾的结论」，
作者必须选一个；后者可能是「这个世界的物体本来就从天而降」（神器、遗产），警告即可。

### D8. `canonlint ledger <世界>` 只读，不改退出码

打印派生状态（每个客体的当前持有者 / 位置）与「没算平的地方」。
**为什么只读**：与 `--impact` 同一条纪律——报告级输出不许改判定结果，也不许让人误以为
「跑一下 ledger 就算改好了」。

### D9. 兼容：旧世界一条不红

示例世界那 27 张 `type: event` 卡是「史料事件」（起源、改编、文献），没有 `when`/`event_kind`。
规则只对**完整事件**生效；`when`/`event_kind` 缺一半才报 CA706。
新字段全部可选 → 协议 1.1 的世界在 1.2 下仍然全绿。**这是硬要求**，有锁。

### D10. 协议版本 1.1 → 1.2

新增 `event_kind` / `when` / `when_sort` / `by` / `to` / `object`（1.4 起另有 `from`）六个字段、`custody_of` 保管断言（1.4）与 CA701–CA710 十条规则。
破坏性改动是允许的（未正式发布），但**旧世界不红**这条不能破。

## 2. 三天怎么走

| 天 | 交付 | 验收 |
|---|---|---|
| 1 | 契约 + 存储 + 六条规则 + `ledger` 子命令 | 六套绿；每条规则有正反用例 |

## 3. 这一版**不做**什么

- 不做「时间区间」（`when_start`/`when_end`）：先把「一笔账一个时刻」做对。
- 不做「可能世界/分支合并」：原著/改编/同人的分叉要等 `superseded_by` 用起来再说。
- 不做「作者断言」的显式标记：现在用「卡上有、流水里没有」来推断，等真出现「我知道我跳过了过程」的需求再加。
- 不做界面、不做酒馆导入：这三天只推进语义与质量。
