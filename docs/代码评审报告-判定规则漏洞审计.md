
## 1. Blocker

### 1.1 `by`/`from`/`to` 腿的窗口校验整块缺位：destroy 后施动、未生者入会、死人收财全部静默

```
[严重度: blocker]
文件: judges/ca/ledger.py:84-96（CA705）、judges/ca/ledger.py:120-135（CA708）
断言: CA705 只把 `death` 记入死亡集合；CA708 只校验 `object` 腿。
      于是：(a) 用 `destroy` 记「死」的角色之后照样出现在 by 腿里；
      (b) join/leave 的 by 在 birth 之前没有任何规则看（腿是 by/to，
      CA708 只查 object）；(c) transfer 的 to 是已死亡角色无人报。
      协议修订 23 自己把 CA705 定为「死人当施动者」、CA708 定为「客体的
      对称线」——对称只做了一半，腿盲缝正好落在两条规则之间。
证据（三组成对实验，对照组均正确报警）:
  W2a 对照: create@1 → death@2 → transfer by:[hero]@3
            → CA705「死人做活事」✓
  W2b 实验: 同结构，death 换成 destroy@2
            → 零报告（CA703 与本断言无关，是 gem 的独立真阳性）
  W3a 实验: join@1 by:[hero] 早于 birth@2        → 零报告
  W3b 实验: death@1 [dead] → transfer@2 to:[dead] → 零报告
建议修法:
  - CA705 的死亡集合并入 `destroy`（或对 character 语义的 destroy 单独定口径）；
  - CA708 扩到 by/from 腿（「不存在的人在做事/从哪里走」）；to 是受方，
    单独定口径（受方也须在窗口内），并给 CA705/CA708 定分工避免双报。
```

### 1.2 CA201 的 `superseded_by` 豁免无状态校验：一行字段关掉查重

```
[严重度: blocker]
文件: judges/ca/duplicates.py:10-18（_supersede_pairs）
断言: 豁免本意是「降级承接对的相似是要求的」，但实现与协议 §6.3 的 CA201 行
      都没校验声明方是不是 archived、承接关系是否成立。superseded_by 写在
      任意状态的卡上都合法（CA101 只在 archived 时要求字段存在，无其他规则
      管它），于是它是一个「数据里的豁免开关」——与协议 §273 自己的立场
      （"不允许数据里的豁免位"）直接冲突。
证据:
  W1a 对照: 两张 canon 卡正文 100% 相同
            → CA201「疑似重复 100%」✓
  W1b 实验: 同上，其中一张加一行 superseded_by: 另一张
            → 零报告，退出码 0（CA401 目标存在、CA405 只看 archived，
              均不触发）
建议修法: 豁免只认声明方 status=archived 的承接对。属改判：先写会红的
      测试，再动 _supersede_pairs，同步协议升号。
```

## 2. High

### 2.1 CA704 的「同刻未定序」= 断言对账的一键降级器

```
[严重度: high]
文件: judges/ca/ledger.py:49-81（ambiguous 跳过断言对账，71-73 行）
断言: 1.10「同刻不拿 id 序裁决」成立，但当前实现把 ambiguous 客体的
      **所有** owns 对账一起跳过——作者补一笔同刻、受方不同的 transfer，
      就能把已触发的 error 降级成 warning 并静默掉断言冲突。
证据:
  W4a 对照: 卡断言 owns gem，流水最终持有者 ccc → CA704 error ✓
  W4b 实验: 补一笔 when_sort 相同、to:[ddd] 的 transfer
            → 只剩「归属未定序」warning，断言对账消失
建议修法: ambiguous 时仍对账「断言者 ∈ 全部受方集合的交集」——交集里
      没有任何断言者照样报，不需要挑赢家。
```

### 2.2 CA711/CA713 多值 `to` 雪崩：一笔坏账静默下游全部校验

```
[严重度: high]
文件: judges/ca/ledger.py:222-249（CA711）、252-276（CA713）
断言: 一笔多值 to 把位置/起点置为 UNDETERMINED 后，**所有**后续 from
      谎报被彻底跳过，直到下一笔单值 to 重新锚定——一个 15 字符的编辑
      就能关掉下游整条轨迹/起点校验。
证据:
  W4d 对照: move@1 to:[loc1] → move@2 to:[loc2] → move@3 from:[loc1]
            → CA711「轨迹断裂」✓
  W4c 实验: move@2 改成 to:[loc2, loc3]（多值，CA702 不报——腿齐全）
            → move@3 的 from 谎报零报告
建议修法: UNDETERMINED 期间声称的 from 与多值集合**完全不相交**时仍报
      「起点无法确认」（warning 口径即可，不必挑位置）。
```

### 2.3 CA712 对写在组织卡上的 member_of 断言失明

```
[严重度: high]
文件: judges/ca/ledger.py:194-219（对账键 (e.id, org)）、
      ledger.py:251-259（member_of_assertions 不限卡侧）
断言: 流水按 (by, org) 建键，断言按 (e.id, org) 建键——member_of 写在

      结构提示；或 CA712 兼容组织卡断言（按 (成员, org) 反查）。
```

### 3.2 CA405 的 referenced 扫描只看索引：遮蔽重复卡上的引用造成二次静默

```
[严重度: medium]
文件: judges/ca/refs.py:75-100（referenced 只扫 index.values()）、
      judges/ca/refs.py:37-46（CA402 对「archived 无承接者」让位给 CA405）
断言: id 重复时后卡不入索引（CA114 已报 error），但它自己的 canon_refs
      边照样被 refs.apply 逐条检查——CA402 对「archived 且无承接者」
      让位给 CA405，而 CA405 的 referenced 扫描看不见不入索引的那张卡，

      不完整」而非逃逸，但同一份违规在不同卡上时有时无地报，会误导排障。
建议修法: CA405 的 referenced 扫描改用 all_entries（与 refs.apply 的
      入参口径一致）。
```

## 5. 设计内 fail-open（已知风险，不算缺陷，但要知道最便宜的全绿通道在哪）

1. **CA703 可以被任何一张卡的 `owns` 断言关掉**（judges/ca/ledger.py:32-46，
   断言无时间，D3 设计）。W7b 实测：受方自己在卡上写 `owns: [gem]`，
   CA703 与 CA704 一起哑火，一笔无源转让全绿通过（W7a 对照正常报 CA703）。
   这是全清单里最便宜的全绿通道，评审侧应作为已知风险记录；若要收紧，
   可给「断言者 == 当笔受方」的情形单独保留 CA703。
2. 同刻 fail-open 家族：CA704/709 同刻未定序、CA712 同刻 join+leave、
   CA705 同刻生死、CA711/713 同刻不排序——方向一致（不拿 id 序裁决），
   本报告 §2.1/§2.2 说的是它们的**反向利用**面。
3. 缺 `when_sort` 不进流水（D2）：CA701/703/705/708/711/713/712 全部
   fail-open；world.schema 已把 when_sort 定为可选排序键，口径一致。

## 6. 验过、堵住的缝（审计阴性结果，可放心的部分）

专门做过坏、结果被堵回来的：

- 规范形 depends_on 省略 kind/critical → CA107 落边（store/model.py:497-510），
  「省注解绕过 CA501/502」的路是堵死的；
- 拼错关系名 → judged_relation_name 真改名建边（store/parse.py:149-164），
  CA110 不再只是嘴上提示；
- 负数流量 → CL108 拒绝 amount ≤ 0（classlint/classlint.py:424-426），
  PE004/PE010 的求和没法被负线灌水；
- owns 走规范形 relations 照样算断言（CA707 对两种写法双向抓，W6c 实测）；
- `--dup-threshold` 的 NaN/∞/0/越界、`when_sort` 的 NaN/bool/inf/字符串、
  YAML 重复键（CA112）、`superseded_by` 坏值/自指——各有守卫在岗。
