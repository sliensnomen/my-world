# 第一次读：五分钟把世界跑起来

> 这篇只做一件事：让你建一个世界、加两张卡、连一条边，并亲眼看到判定器报出第一条错误。
> 术语卡住时翻 [术语表](术语表.md)；想知道每条规则判什么，查 [判定规则总表](判定规则总表.md)。

## 0. 装依赖

需要 Python 3（CI 在 3.12 / 3.14 上验证），以及 `pyyaml`：

```bash
python3 --version
pip install pyyaml
```

## 1. 建一个世界

在仓库根目录执行：

```bash
python3 canonlint.py init ~/worlds/grey-harbor
```

你会看到：

```text
提示：git init 后重跑本命令可装 pre-commit 钩子
世界仓库已初始化: /home/你/worlds/grey-harbor
下一步: canonlint new location 灰港
```

最后一行路径会随你的 HOME 变化。`init` 建出的目录就是「一个世界」：条目之后会放进
`entries/`（第一张卡建出来时才出现），`CONSTITUTION.md` 是世界宪章。想让世界进 Git，
先 `git init` 再重跑一次 `init`，它会顺手装 pre-commit 钩子。

## 2. 加两张卡

```bash
python3 canonlint.py new --root ~/worlds/grey-harbor location 灰港 --id grey-harbor
python3 canonlint.py new --root ~/worlds/grey-harbor faction 王都 --id crown-capital
```

输出：

```text
已建卡: entries/locations/grey-harbor.md（draft）
已建卡: entries/factions/crown-capital.md（draft）
```

打开 `entries/locations/grey-harbor.md`，上面那段 `---` 包起来的就是卡面：

```yaml
id: grey-harbor
title: 灰港
type: location
status: draft
load_bearing: false
```

`id` 是稳定标识，`type` 决定它是地点、势力还是人物，`status` 是生命周期
（`draft → trial → canon`，退役用 `archived`），`load_bearing` 表示它是不是承重墙。
下面的正文才是设定本身。

## 3. 连一条边

灰港的财政依赖王都：

```bash
python3 canonlint.py link --root ~/worlds/grey-harbor grey-harbor crown-capital --kind fiscal --critical
```

```text
已连线: grey-harbor --fiscal(critical)--> crown-capital
记得跑 canonlint 检查这条边是否合法（层级方向/环/状态）
```

`fiscal` 是依赖类别（财政），`critical` 表示这是关键依赖——改王都，灰港会受波及。
这条边写进 `entries/locations/grey-harbor.md` 的 `depends_on`，不是单独的关系文件。

## 4. 让判定器看一眼

```bash
python3 canonlint.py ~/worlds/grey-harbor
```

```text
2 个条目 | 0 错误 | 0 警告
```

退出码 `0`。到这里，你已经有一个能通过审计的最小世界。

## 5. 看它抓一条真错

把王都那张卡删掉，模拟「引用断了」：

```bash
rm ~/worlds/grey-harbor/entries/factions/crown-capital.md
python3 canonlint.py ~/worlds/grey-harbor
```

```text
[CA401] error   entries/locations/grey-harbor.md: depends_on 引用指向不存在的 id `crown-capital`

1 个条目 | 1 错误 | 0 警告
```

退出码变成 `1`。这就是这个项目的核心：不是告诉你「写得像不像」，而是告诉你
「这条依赖指向的条目根本不存在」。把卡加回来，审计又回到 0：

```bash
python3 canonlint.py new --root ~/worlds/grey-harbor faction 王都 --id crown-capital
python3 canonlint.py ~/worlds/grey-harbor
```

## 6. 多走一步：改它之前，先看会波及谁

```bash
python3 canonlint.py ~/worlds/grey-harbor --impact crown-capital
```

```text
[CA504] report  crown-capital: 下游待复核 → ['grey-harbor']

2 个条目 | 0 错误 | 0 警告
```

`report` 只报告，永远不进退出码。它回答的是「改这张卡，哪些卡要跟着复核」。

## 你现在知道了

- **世界**是一个目录；**条目**是一张 Markdown 卡；**关系**是卡与卡之间的有向边。
- 判定是确定性的：同一份输入，永远同样的 findings、同样的退出码。
- 一条 finding 至少告诉你三件事：规则编号、级别、哪张卡的哪个字段。

## 两个容易踩的坑

1. **`classlint` 是另一层工具，读的是 `codex/`，不是 `entries/`。** 它有自己的 `init`，
   命令是 `python3 classlint/classlint.py ...`，规则是 CL/PE。目前两层还没有合并成
   一个世界目录，别把两套命令混着跑。详见 [classlint/README.md](../../classlint/README.md)。
2. **1.x 与 2.0 不是同一个东西。** 这篇跑的是 1.x 卡面工具（维护态）；2.0 是以事件为
   唯一事实源的文字世界模型，契约在 `spine/`，路线见 [CHARTER.md](../../CHARTER.md)。
   第一次读先不用碰 2.0。

退出码速查：`0` 通过；`1` 有 error（`--strict` 时 warning 也算）；`2` 用法或环境错误；
classlint 的 `3` 表示有 PE 规则被关掉、判定不完整（见 [classlint/PROTOCOL.md](../../classlint/PROTOCOL.md) §4）。
