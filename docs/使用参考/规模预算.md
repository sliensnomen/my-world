# 规模预算与性能基线

**状态**：现行（2026-11-23 建立，issue #15）
**用途**：给“世界能长多大、接口多快算够用”一个可复现的尺子；超过预算不是 bug，
但必须在这里记下来，不能悄悄变慢。

## 目标规模

| 维度 | 预算 | 说明 |
|---|---|---|
| 条目数 | ≤ 1000 | 单机单世界；超过要先重测再放宽 |
| 平均正文 | ≤ 2000 字 | 查重的候选过滤与正文长度相关 |
| 每卡关系数 | ≤ 10 | 典型世界远低于此 |

## 延迟预算（单机基线，参考机为开发机）

| 操作 | 预算 | 实测（2026-11-23，1000 条目 / 正文 2000 字） |
|---|---|---|
| `canonlint check`（冷，含全部判定） | ≤ 10 s | 6.9 s |
| `canonlint export`（冷，含全部判定） | ≤ 10 s | 6.3 s |
| `GET /api/health`（冷） | ≤ 10 s | 6.4 s（首次请求要跑完整审计） |
| `GET /api/health`（热） | ≤ 100 ms | 22 ms |
| `GET /api/entry/<id>`（热） | ≤ 100 ms | 36 ms |
| `GET /api/world`（热） | ≤ 150 ms | 30 ms |

“热”指世界文件没有变化、服务端导出缓存命中。缓存的失效键是**整目录
`(相对路径, size, mtime_ns)` 指纹**：任何写入（CLI 或写接口）都会改
mtime/size，下一次请求重新审计，不会拿旧数据糊弄。

## 复现方式

```bash
python3 tests/bench_scale.py --entries 100,1000 --body 2000
```

脚本会临时生成合成世界（正文由词表洗牌，接近“互不相似”的常见情况），
打印 `audit_ms` / `export_ms` / HTTP 冷热耗时。结果应按机器记录在这里或
issue 里，不要只留在聊天记录。

## 已知边界（明确不做的事）

- 冷请求仍要跑完整审计：1000 条目约数秒，这是语义要求（任何改动后都必须重新判定），
  不缓存“半份真相”。
- 查重是 O(n²) 候选对上的便宜过滤：先按字频上界、8 字 shingle 样本重合率剪掉
  明显不可能重复的对，再进 `difflib.SequenceMatcher`。过滤只剪“上界低于阈值”的
  对，召回率不变（`tests/run_tests.py` 的 CA201 用例会报出 85% 相似的近重复）。
- `/api/entry` 目前复用整份导出（热路径走缓存），不为单条读单独建解析器——少一处
  会与 `/api/world` 漂移的代码；千条目级热请求已在预算内。
- 超过 1000 条目或正文显著变长时，先跑基准再判断是否需要“候选集分桶/倒排索引”；
  没有实测热点之前不加复杂度。
