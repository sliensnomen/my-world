# 2.0 第一个发行版计划（目标：2027-01-20）

**日期：2026-11-23 ｜ 状态：现行 ｜ 读者：用户与对稿 AI**
**资源前提：每周 <10 小时 × 8 周 ≈ 70 小时；主力 = 用户 + AI；抽取走用户自己的 LLM 渠道**

## 一句话

canonlint 2.0 第一个发行版 = **一台事件账本工具**：从成熟小说抽事件（冰火，内部基准），
人确认入账，确定性规则审计穿帮。仓库 clone + `./install.sh` 一次跑通，就叫 canonlint。

## 底线与头条（Q5 裁决的产物）

- **底线（必须交）：能记录、能审计。** `spine record` 记事件 → 投影当前态 → 结构审计
  出报告。这是最小可用产品，砍什么都不能砍它。
- **头条（应该交）：冰火抽取基准跑通。** 前 N 章抽取 → 确认 → 与手工卡基线对账，
  准确率/召回率各一个数。这是「文字世界模型」的故事证据。
- **熔断**：W4 末抽取 precision < 60%（确认成本高于手工记账）→ 砍头条，release 退守底线。
  熔断不退方案，只退叙事。

## 砍掉的（明确不做）

推演；LLM 回流管裁决（v2.0.0 里 LLM 只做抽取，不做裁决）；红楼全本基准；pip 打包；
2.0 的 web 界面（写轨只 CLI）；巫王世界创作轮。

## 风险与二阶推演

1. **抽取质量是最大不确定项**：precision 太低会让「人确认」变成「人重写」，闭环成本倒挂。
   对策 = W4 熔断线（见上）。
2. **投影语义坑**：同刻/未定序在 1.x 修了一年（CA704/709/714）。对策：只移植 1.x 已收敛的
   子集（owns/custody/位置/成员四轴 + 同刻未定序），不贪全；边界案例进 spine 回归网钉死。
3. **规则数量即维护成本**：v2.0.0 的规则刻意保持小（结构族 ≤10 条），每条都走协议升号纪律；
   规则少 = 维护便宜 = 1.x 维护态承诺扛得动。
4. **双套件并存期**：spine 与 1.x 六套并跑到切换日，CI 已接、依赖方向锁已守；切换日后
   1.x 进 `attic/1.x/`。长期成本主控点：2.0 代码量目标 < 2000 行。
5. **维护态文案时点**：随 release 公告落 main README（1 月），不提前说「维护态」——
   2.0 还没影时写维护态是空话。
6. **版权**：冰火抽取库只限内部基准（宪章 §9）；随发行版的 demo 数据集用红楼公版小样。

## 底层需求复盘（立此存照）

「出发行版」是症状，底层需求是「**在硬日期前有一个能拿出来给人看的、真实可跑的
转型证据物**」。所以每周验收都钉在可演示的证据上：闭环录屏、对账数字、审计报告、
install.sh 一次跑通。任何一周拿不出证据，当周就算脱轨，下周砍范围不回头的补。

## 验收总闸（01-20 当天能说什么）

- 「`./install.sh` 然后 `./spine record` 三笔记账，`./spine audit` 出报告」——底线证据；
- 「冰火前 N 章机器抽取，precision X% / recall Y%，与手工卡基线对账」——头条证据；
- 「红楼小样随包可跑」——版权干净证据。
