# 2.0 第一个发行版计划 v2（目标：2027-01-20）

**日期：2026-11-23（v2 修订） ｜ 状态：现行 ｜ 读者：用户 + 复核 AI 群**

> v2 修订缘由：能力覆盖盘点（canonlint 1.x 对计划的覆盖约三分之二）改变了风险分布——
> 底线几乎全是移植（低风险），头条是唯一的零覆盖模块（高风险）。v2 把计划改写为
> **可复核形态**：每个承重假设给出处，每周容量给核算，复核指南单列。

## 0. 给复核 AI 的话（先读这节）

本计划故意把所有可 falsifiable 的主张摆上台面。复核时请按攻击强度排序打这些靶：

1. **容量核算**（§4）：每周 ≤10h 的估算是不是自欺欺人——哪一项你觉得低估了，给数字。
2. **覆盖主张**（§3）：我说的「移植」是不是真的移植——到 1.x 源码里抽查锚点
   （`ledger.py` 的 `derive_state`、`judges/ca/ledger.py` 的 CA7xx 实现、`canonlint.py`
   的 `event` 子命令），判定「改输入源」的工作量我是不是说小了。
3. **熔断线**（§2）：precision <60% 砍头条——60% 这个数字有没有依据？欢迎推翻。
4. **对账方法论**（§5）：recall 的分母定义是否成立，有没有更诚实的定义。
5. **砍掉清单**（§6）：哪一项砍错了，会给发行版留下致命短板？

复核纪律（沿宪章 §7）：引用仓库事实必须附 HEAD 短哈希与命令输出；主张「零结果」
必须附搜索命令本身。本计划基准：分支 `2.0`，HEAD `39d787f`。

## 1. 是什么

canonlint 2.0 第一个发行版 = **一台事件账本工具**：从成熟小说抽事件（冰火，内部基准），
人确认入账，确定性规则审计穿帮。仓库 clone + `./install.sh` 一次跑通。名字不动，
仍叫 canonlint；卡面 1.x 进维护态（承诺文案随 release 公告落 main）。

**底层需求复盘**（每次修订都要重做）：「出发行版」是症状；底层是「硬日期前拿出一个
真实可跑的转型证据物」。所以每周验收钉可演示证据，拿不出 = 脱轨，下周砍范围不回头补。

## 2. 底线与头条

- **底线（必须交）：能记录、能审计。** `spine record` 记事件 → 投影当前态 → 结构审计
  出报告 + 红楼公版小样 demo。砍什么都不能砍它。
- **头条（应该交）：冰火抽取基准跑通。** 前 N 章抽取 → 确认 → 对账，准确率/召回率各一个数。
- **熔断**：W4 末（12-21）precision <60% → 砍头条，release 退守底线。熔断退叙事不退方案。
  - 60% 的依据：低于它，「人确认」逐条改的成本高于手工记账（闭环成本倒挂，
    抽取器从帮手变负担）；该阈值可在 W3 实测确认成本后修订。

## 3. 覆盖主张（1.x 资产盘点，复核锚点）

**移植（低风险）**：投影引擎（`ledger.py` `derive_state`，四轴 + certainty 三态 +
同刻不排序）；记账 CLI（`canonlint.py` `event` 子命令）；结构审计族（`judges/ca/ledger.py`
的 CA701/702/705/708/711/714/716/717/720，判据保留、输入源从「卡+流水」改纯事件流）；
id 索引与引用完整性（`store/`）；规则注册架构（`judges/` Registry）；测试手法
（夹具+快照+意图断言+AST 锁，`spine/tests/` 已在跑）。

**全新（风险集中处）**：LLM 抽取器（1.x 零 LLM 调用）；确认流（CA504「工单化」只有
概念原型，无交互确认界面）；对账脚本（小）；install.sh / release 面（机械活）；
红楼 demo 小样（内容活，手校）。

**减法**：实体卡消亡，断言住处换成期初事件（`spine/migrate.py` 已写，`type: import`）；
双源对账族（CA703/704/709/713）随卡面陪葬，不移植（宪章 §6）。

**刻意不进 v2.0.0 的 1.x 能力**：classlint PE 族、econ 包、web 界面、serve 写路由——
留在 1.x 维护态，这不是缺口是范围控制。

## 5. 对账方法论（复核靶点）

基线 = `world-westeros` 手工卡经 `spine/migrate.py` 转成的事件集。
- **recall 分母** = 基线中来源锚点落在所选章节范围内的事件数（不是基线总数——
  基线覆盖跨卷事件，超出所选章节的不可计）。
- **precision 分子** = 抽取事件中与基线匹配的条数；不匹配条目**人工抽检**定误判率，
  抽检比例与规则写进对账脚本输出。
- `source: import` 的期初建台区块整段不计入评分（与手工卡没有可比口径，宪章 §5）。

## 6. 砍掉的（明确不做）

推演；LLM 回流管裁决（v2.0.0 里 LLM 只抽取不裁决）；红楼全本基准；pip 打包；
2.0 web 界面（写轨只 CLI）；巫王世界创作轮（用户 2026-11-23 裁决放弃，语料改用
成熟小说）。

## 7. 风险与二阶推演

1. **抽取质量**是唯一可能炸头条的变量：precision 太低 → 确认成本倒挂 → W4 熔断。
   熔断后头条位由「红楼小样 + 审计报告」顶替，release 不空。
2. **投影语义坑**：同刻/未定序在 1.x 修了一年（CA704/709/714）。只移植已收敛子集；
   边界案例当场进 spine 回归网钉死，不许「先记着以后补」。
3. **规则数即维护成本**：v2.0.0 结构族 ≤10 条，每条走协议升号纪律；规则少 =
   1.x 维护态承诺扛得动。
4. **双套件并存期**：CI 已接 spine（带主干守卫），依赖方向 AST 锁在跑；切换日后
   1.x 进 `attic/1.x/`。长期成本主控点：2.0 代码量目标 <2000 行。
5. **维护态文案时点**：随 release 公告落 main（1 月），不提前说空话。
6. **版权**：冰火抽取库只限内部基准；随包 demo 用红楼公版小样（宪章 §9）。
7. **每周证据纪律**：当周验收的输出文本/对账数字存 `spine/evidence/wN-*` 入库；
   拿不出的周 = 脱轨，下周砍范围。

## 8. 验收总闸（01-20 当天能说什么）

- 「`./install.sh` 然后 `./spine record` 三笔记账，`./spine audit` 出报告」——底线证据；
- 「冰火前 N 章机器抽取，precision X% / recall Y%，与手工卡基线对账」——头条证据；
- 「红楼小样随包可跑」——版权干净证据。
