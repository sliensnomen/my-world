## 0. 给复核 AI 的话（先读这节）

本计划把所有可 falsifiable 的主张摆上台面。复核时请按攻击强度排序打这些靶：

1. **容量核算**（§4）：余量只有 ~1h——哪一项你觉得还会爆，给数字。
2. **覆盖主张**（§3）：「移植」是不是真的移植——抽查 1.x 锚点（`ledger.py`
   `derive_state`、`judges/ca/ledger.py` CA7xx、`canonlint.py` `event` 子命令）。
3. **熔断线**（§2）：precision 阈值的样本量与置信区间。
4. **对账方法论**（§5）：匹配键与分母定义。
5. **砍掉清单**（§6）：哪一项砍错了。

复核纪律（沿宪章 §7）：引用仓库事实必须附 HEAD 短哈希与命令输出；主张「零结果」
必须附搜索命令本身。

## 1. 是什么

canonlint 2.0 第一个发行版 = **一台事件账本工具**：从成熟小说抽事件（冰火，内部基准），
人确认入账，确定性规则审计穿帮。仓库 clone + `./install.sh` 一次跑通。名字不动，
仍叫 canonlint；卡面 1.x 进维护态（承诺文案随 release 公告落 main）。

**底层需求复盘**：「出发行版」是症状；底层是「硬日期前拿出一个真实可跑的转型证据物」。
每周验收钉可演示证据，拿不出 = 脱轨，下周砍范围不回头补。

## 2. 底线与头条

- **底线（必须交）：能记录、能审计。** `spine record` 记事件 → 投影当前态 → 结构审计
  出报告 + 红楼公版小样 demo。砍什么都不能砍它。
- **头条（应该交）：冰火抽取基准跑通。** 前 N 章抽取 → 确认 → 对账，准确率/召回率各一个数。
- **熔断**：W4 末（12-21）**raw_precision** <60% → 砍头条，release 退守底线。
  熔断只对 raw（模型原始候选、未经人工修改）生效，退叙事不退方案。
  - 阈值注意（评审 P0-3）：第一章样本量小，60% 只是占位；W4 定稿时必须附
    样本量与置信区间（双人标注一致性若可及则一并报），否则 W4 后再定阈值。

## 3. 覆盖主张（1.x 资产盘点，复核锚点）

**移植（低风险，输入源从「卡+流水」改纯事件流）**：投影引擎（`ledger.py`
`derive_state`：holder/custodian/location 三轴 + membership 单列 + certainty 三态 +
同刻不排序）；结构审计族（`judges/ca/ledger.py` 的 CA701/702/705/708/711/714/716/717/
719/720）；id 索引与引用完整性（`store/`）；规则注册架构（`judges/` Registry）；
测试手法（夹具+快照+意图断言+AST 锁，`spine/tests/` 已在跑）。

**移植的真坑（评审 P0-2，W1 的门槛）**：形状差异——1.x 是 `type: event` + `event_kind`，
2.0 是 `type: <kind>`；`ledger.py` 的 `is_event_card` 只认前者，迁移产物不能直接喂
1.x 引擎；`derive_state` 忽略 `type: import`；`derive_membership` 不认
`x-import-kind: member`；CA719 读卡面 `member_of`；CA717 依赖实体卡 `type`
（实体卡消亡后会静默空转）；`canonlint event` 写的是 1.x 卡。——所以 W1 第一件事是
**适配层**，不是「直接移植」。

**全新（风险集中处）**：LLM 抽取器（1.x 零 LLM 调用）；确认流（v3 前误挂 CA504
「工单化」——评审纠正：CA504 是只读 impact，确认状态机按 §5-乙独立定义）；对账脚本；
install.sh / release 面；红楼 demo 小样。

**减法**：实体卡消亡，断言住处换成期初事件（`spine/migrate.py`，`type: import` +
`x-import-kind`）；双源对账族（CA703/704/709/713）随卡面陪葬；`certainty=ambiguous`
在 v2.0.0 只展示不审计（替代规则进 backlog）。

**刻意不进 v2.0.0 的 1.x 能力**：classlint PE 族、econ 包、web 界面、serve 写路由。

## 5. 对账方法论（评审 P0-1/P0-3 已并入）

基线 = `world-westeros` 手工卡经 `spine/migrate.py` 转成的事件集。

- **排除规则按 `type` 不按 `source`**（P0-1 的真 bug 修复）：期初建台 = `type: import`
  （带 `x-import-kind`），整段不计入评分；真实事件（`type: transfer` 等）即使
  `source: import` 也计入——迁移 24 笔中 19 笔真实事件是分母，5 笔建台不是。
- **章节锚点**：用手工卡 frontmatter 的 `x-chapter`（两个 schema 的 `^x-` 均已放行，
  不动 `additionalProperties: false`，不升契约）；`spine/migrate.py` 原样带进事件。
  recall 分母 = 基线中 `x-chapter` 落在所选章节范围内的真实事件数。
- **两组指标**（P0-3）：`raw_precision/raw_recall`（模型原始候选）与
  `confirmed_precision`（确认后账本）；熔断只对 raw。
- **匹配键**：`type` + 归一化腿（排序后的 id 集合）+ 时间窗（`when_sort` 容差 ±0）。
  一对多规则：一笔基线只许被一笔抽取命中，多命中按一正一误计。
- **precision 分子** = 命中的抽取条数；不匹配条目人工抽检定误判率，抽检比例与
  规则写进对账脚本输出；裁决人 = 用户本人。

## 5-乙. 确认流协议（评审 P0-3 新立，不挂靠 CA504）

- 候选状态机：`pending → accepted / edited / rejected`；`edited` 留修改前后两份；
  `rejected` 必填理由；`confirmed_by` / `confirmed_at` 落审计列（永不进投影）。
- 确认记录可重放：JSONL 追加日志（谁、何时、对哪条候选做了什么），回滚 = 按日志
  逆放；W3 产出 = 候选 JSONL + 状态机 + 可重放确认记录。
- CLI 确认流只三键：`y`（收）/ `e`（改后收）/ `n`（拒，填理由），`s` 跳过留 pending。

## 6. 砍掉的（明确不做）

推演；LLM 回流管裁决（v2.0.0 里 LLM 只抽取不裁决）；红楼全本基准；pip 打包；
2.0 web 界面（写轨只 CLI）；巫王世界创作轮（用户 2026-11-23 裁决放弃）。

## 7. 风险与二阶推演

1. **头条主要炸点是抽取质量**：raw precision 太低 → 确认成本倒挂 → W4 熔断；
   熔断后头条位由「红楼小样 + 审计报告」顶替，release 不空。（评审小项：
   确认流、install、发布流程同列风险，见 5/6/7。）
2. **适配层是 W1 的真门槛**：形状差（`type: event`+`event_kind` vs `type: <kind>`）
   不解决，投影与 CA7xx 全在空转——差分测试是 W1 的完成定义。
3. **投影语义坑**：同刻/未定序在 1.x 修了一年。只移植已收敛子集；边界案例当场进
   spine 回归网钉死。
4. **规则数即维护成本**：v2.0.0 结构族 ≤10 条，每条走协议升号纪律。
5. **确认流是新代码不是原型**：状态机/留痕/回滚做小了就够用，做大了拖死 W3——
   三键 CLI 为止，不提前做 web。
6. **双套件并存期**：CI 已接 spine（带主干守卫），依赖方向 AST 锁在跑；切换日后
   1.x 进 `attic/1.x/`。长期成本主控点：2.0 代码量目标 <2000 行。
7. **版权**：冰火抽取库只限内部基准；随包 demo 用红楼公版小样（宪章 §9）。
8. **每周证据纪律**：当周验收的输出文本/对账数字存 `spine/evidence/wN-*` 入库；
   拿不出的周 = 脱轨，下周砍范围。

## 8. 验收总闸与发布清单（评审 P1-2 已并入）

01-20 当天能说的三句话：
- 「`./install.sh` 然后 `./spine record` 三笔记账，`./spine audit` 出报告」——底线证据；
- 「冰火前 N 章机器抽取，raw precision X% / recall Y%（n=…，区间=…），与手工卡
  基线对账」——头条证据；
- 「红楼小样随包可跑」——版权干净证据。

W8 发布清单：合并 main、`attic/1.x/` 迁移、main 分支保护与 1.x 维护 CI 就位、
回滚演练（`git revert` 发行提交）一次、干净机 clone→install→record→audit 端到端
冒烟一次（三个命令在 W8 前必须真实存在且跑通，不只看 W6 的 install）。
