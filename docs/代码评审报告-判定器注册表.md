## 4. 本任务 TDD 与实现

### RED

- 默认后端：focused 调用 `check_registry_loading_matrix()`，exit 1，输出「缺省 WGP_JUDGE_BACKEND 必须选择 registry」。
- serve 失败时点：focused 调用 `check_非法后端在审计与绑定前失败()`，exit 1；实际为未捕获 `RegistryError`，而不是干净退出码 2。

### GREEN

- `judges/registry.py` 只把缺省值改为 `registry`，显式 `legacy` 不变。
- `serve.py` 在调用 `serve()` / `ThreadingHTTPServer` 之前加载 Pack 并捕获 `RegistryError`，输出环境错误且返回 2。
- focused 默认/回退测试通过；focused serve 测试确认审计与绑定函数均未调用，stdout 为空。
- 真实进程 `WGP_JUDGE_BACKEND=future python3 serve.py tests/world-arrakis --port 0`：exit 2、stdout 空、stderr 指明变量、无 traceback。

CI 不增加 matrix 维度，避免改变分支保护依赖的四个检查名；每条测试命令都在同一检查内依次以 `registry`、`legacy` 执行，因此六套均双后端覆盖。

## 6. 作者自审与评审焦点

作者自审重点：默认只改一处；CLI/serve 没有各自分叉选择后端；非法值在任何审计和 bind 前失败；legacy 文件与协议版本未删除/修改；CI 检查名保持稳定；文档没有声称观察期已过。

请独立评审核对：

1. 完整变更中的执行日程、遍历域、真实 Finding、原始/出口排序和外部行为是否确实等价；
2. serve 的 Pack/后端错误是否均在审计与端口绑定前失败，是否可能留下部分结果；
3. CI 是否真实覆盖六套 × 两后端，legacy 回退是否仍可执行；
4. HTTP 写双跑是否使用独立世界副本，比较是否仅排除事先声明的 Date、端口和 ts；
5. 是否存在未解决 Critical/Important。若有，必须先补 RED，再修复并重跑双后端六套；Minor 单独记录。
