# 给前端的说明（v1）。

## 一、你要做的事

一句话：**我们给你一份 JSON，你把它画出来。**

内置 `web/index.html` 已经有台账 / 审计 / 流水 / 工单 / 记账五个视图。这里说的后续独立界面第一屏是**思维导图**：中间一个条目，四周是它的关系；点一下别的条目，就换成新的中心。地图再后面。

## 二、数据从哪来

### 今天就能用：JSON 文件

```
python3 canonlint.py export tests/world-arrakis --out world.json
```

`tests/world-*` 下面有 9 个世界，随便挑一个导出。导出的 JSON 是**只读快照**，不要写回。

### 这是本地浏览器端口，你让他在这里写

```
cd <你克隆下来的仓库目录>

python3 serve.py tests/world-arrakis        # 打开 http://127.0.0.1:8000
```

接口**已经能用了**，不用等。起服务之后这几个地址直接给 JSON（和上面导出的那份逐字段一致，有测试钉着）：

- `GET /api/world` —— 整个世界
- `GET /api/entry/<id>` —— 单个条目 + 它的进边和出边
- `GET /api/raw/<path>` —— 原始 Markdown（只读；隐藏文件/目录不给，`404`）
- `POST /api/entry`、`POST /api/event`、`POST /api/status` —— 写卡/记账/升格（**仅 `--writable` 时**；默认只读）
- `GET /api/health` —— 存活 + 数量速览

细节（curl 例子、写入口与同源规矩、坏文件怎么显示）见 `docs/接口说明.md`。

解析器 `wgp-client.js` 在仓库根：它补默认值、建索引、标出指不到人的边，一行拿到思维导图要的形状：

```js
WGP.load("/api/world").then(w => w.mindmap("bene-gesserit"))
```

把前端文件放进仓库根下的 `web/`（与 `serve.py` 同级），用 `/web/index.html` 打开：同源，不用管 CORS。

## 四、字段是什么意思

**entries\[\]（一个条目一条）**

| 字段 | 意思 |
| - | - |
| `id` | 条目的唯一名字。**文件坏了时是 `null`** |
| `path` | 文件路径。`findings` 里的 `entry` 用的是同一个值，靠这个对得上 |
| `title` / `type` / `status` / `layer` | 标题 / 种类 / 正式程度 / 属于世界的哪一层（`layer` 可能没有） |
| `author` / `date` | 谁写的、首次定稿日期（ISO 日期） |
| `load_bearing` | `true` = 承重墙，世界的骨架，**视觉上要区分** |
| `ai_assisted` | 是否 AI 参与写的 |
| `superseded_by` | 被哪条取代了，没有就是 `null` |
| `when` / `when_sort` | 事件字段：故事内时间（自由文本）/ 时序排序键（数字）。不是事件卡就是 `null` |
| `event_kind` | 事件种类：`transfer` / `custody` / `move` / `create` / `destroy` / `grant` / `birth` / `death` / `join` / `leave` / `transform`，或 `x-` 实验值 |
| `by` / `to` / `object` / `from` / `result` | 事件腿（id 列表）：施动者 / 受方 / 客体 / 起点（move、leave）/ transform 的产物 |
| `owns` / `custody_of` / `member_of` | 断言（id 列表）：本卡拥有 / 保管 / 属于哪些组织。与卡上的写法一致，前端原样渲染即可 |
| `parse_error` | **不是 `null` 就表示这个文件读不出来** |
| `body_excerpt` | 正文前 200 字 |
| `body_chars` | 正文字数（**去掉首尾空白**后算；`body_excerpt` 的截断也按这个长度）。空白不算字数，是因为正文从围栏之后开始，直接数会把开头那个空行也算进去 |
| `x_fields` | 作者自定义的字段（`x-` 开头），原样显示就行 |
| `relations` | 从这个条目出去的边（和 `relations[]` 里的是同一批） |


**relations\[\]（一条边一条）**

| 字段 | 意思 |
| - | - |
| `source` / `type` / `target` | 从谁、什么关系、到谁 |
| `kind` | 只有 `depends_on` 有：靠**哪一类物资**供养（`resource` / `production` / `economy` / `fiscal` / `manpower`，别的值当实验值看） |
| `critical` | `depends_on` 与 `derives_legitimacy_from` 有：缺了行不行 |
| `stance` | 有的边有立场：`official` / `heretic` / `unknown` |
| `note` | 有的边有备注 |


**dangling\[\]（指不到人的边）**

| 字段 | 意思 |
| - | - |
| `source` / `type` / `target` | 和 `relations[]` 里一样的三件事 |
| `reason` | `missing-id` = 真没这条条目；`world-ref` = 指向别的世界（本版不支持） |

**`counts`**：`entries`（条目数）/ `unparsed`（读不出来的文件数）/ `relations`（边数）/ `dangling`（断链数）/ `assets`（大文件数）/ `findings` / `errors` / `warnings` / `infos`。

**`ledger`**：派生状态——期初断言 + 事件流水算出来的「现在谁拿着什么」。
`states`：客体 → `{holder, holder_source, custodian, location}`（持有者/来源/保管/位置，没有的键是 `null`）；
`membership`：人 → `{组织: "join" | "leave"}`（流水里的最后一个动作）。
没有流水就是 `{"states": {}, "membership": {}}`。这组数据与 `canonlint ledger` 子命令同出一处，前端直接渲染，不要自己重算。

**`vocabularies`**：`types` / `statuses` / `layers` / `kinds` / `stances` / `relation_types` / `fields`，
每个都是「值 → 出现次数」。**画图要用的名字从这里取，不要写死。**

**`findings`\[\]**：`rule`（规则号）/ `level`（`error` / `warning` / `info`）/ `entry`（哪个文件）/ `message`。第一屏可以不管。

**`reports`\[\]**：`rule` / `subject` / `downstream`——影响范围，要 `--impact` 点名才有，第二步再说。

**`assets`\[\]**：`path` / `bytes`——地图之类的大文件，现在都是空的。

顶层还有 `protocol_version` 与 `contract_version`：数据格式的版本号，我们改了会告诉你。

## 五、四条画图规矩

1. **关系名原样显示**。名字的含义在 `world.schema.json` 的 `x-relation-vocabulary.names`（每个名字都带 `means`），**不要翻译、不要按名字判断对错**。目前常见的是 `depends_on`（靠它活着）/ `derives_legitimacy_from`（说法以它为依据）/ `canon_refs`（叙事引用）/ `exchanges_with`（互相交换）/ `conflicts_with` / `controls` / `owns` / `extracts` / `coerces` / `legitimizes` / `owes`，别的名字也可能出现。

2. **种类名和层名从 `vocabularies` 里取，不要写死**。以后加种类时，你不用改代码。

3. **指不到人的边要标红、不要藏**。`target` 不在 `entries` 里就是这种情况，`dangling[]` 里同时给了原因：`missing-id`（真没这条）或 `world-ref`（指向别的世界）。

4. **坏文件也要显示出来**。`parse_error` 不是 `null` 的条目，灰色显示文件名 + 错误信息就行。咱们做的**工具最该让人看见的东西之一**，不能丢。

页面角落放上 `protocol_version` 和 `contract_version` 两个号就行。

## 六、你不需要做的事

- 不需要解析 Markdown（我们不给你 Markdown，只给 JSON）。

- 默认不需要做写操作（接口默认只读）；`--writable` 时的写表单是加分项，不是第一屏的验收条件。

- 不需要自己造测试数据（用真数据，见第七节）。

## 七、怎么算第一屏做完

拿我们给的 JSON 试，任何一条都算数：

1. **换一个世界的 JSON，不改代码，图能出来**（数据：`tests/world-arrakis` 22 个条目、`tests/world-westeros` 42 个、`tests/world-middle-earth` 14 个）。

2. 点任意条目，都能换成中心。

3. 悬空边看得见 —— 用 `tests/world-bad` 试，它有 3 条悬空：`bad-refs` 指 `ghost-entry`（目标不存在）、`bad-refs` 指 `otherworld:shared-lore`（跨世界引用）、`dup-entry` 指 `ghost-nowhere`（目标不存在）。

4. 坏文件条目看得见 —— 用 `tests/world-crash` 试，它有 1 个（`entries/bad-utf8.md`）。

5. 承重墙条目一眼能认出来。

## 八、说好了就不改的部分

`entries[]` 和 `relations[]` 里的字段名，是两边说好的合同。 我们要动它，会先通知你，并且我们这边有测试兜底；反过来，请不要自己给字段加别的意思。 JSON 里的 `contract_version` 就是这个合同自己的号。
