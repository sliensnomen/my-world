# 协作流程：git 工作流 ↔ 世界状态机

本文件讲两件事：

- **一 ~ 三节**：世界数据仓库（你写的那个世界）里怎么用 git 管设定，以及该跑什么门禁；
- **四节**：本工具仓库（canonlint 源码）自己的协作机制。

协议不规定权限模型（`PROTOCOL.md` §6.2 审计中立性条款），治理密度是地方事务：
全部用 forge（GitHub / Gitea）的现成机制拼装，零自研。

## 一、状态机 ↔ git 操作（世界数据仓库）

| 协议动作 | git 操作 |
|---|---|
| 新建提案（`status: draft`） | 分支写条目 → PR |
| draft → trial | PR 改 `status`，跑过一场桌后合并 |
| trial → canon | PR 改 `status`；CODEOWNERS 强制评审组 approve，CI 必须绿 |
| canon → archived | 降级 PR：必须同时填 `superseded_by`，CI 贴 CA504 下游清单作为复核工单 |
| archived → trial/canon | 恢复 PR，默认重走升格；快速通道由该仓库的宪章声明 |
| 矛盾标注 | PR 给双方条目加 `conflicts_with`，**不阻塞**任何合并（矛盾合法化） |

**条目位置**：今天 `canonlint init` 建的是 `entries/{type}/`，`new` 也写在那里。
但**格式不靠路径表达意义**——判定的对象是 frontmatter 里的字段，不是文件放在哪；
`world.schema.json` 是格式契约，路径约定只是 `init` 的默认值。

## 二、门禁：世界数据仓库该跑什么

```bash
python3 canonlint.py . --strict                # error 与 warning 都拦（CI 门禁用）
python3 canonlint.py . --json --impact <id>    # CA504：本次改动的下游待复核清单（只读）
python3 canonlint.py . --pack econ             # 启用 econ 扩展包（CA601/CA602）
```

- 不带 `--strict` 只拦 error；`--strict` 连 warning 一起拦。
- **`report` 级别的输出永不进退出码**：CA504 影响报告、`graph`、以及未来的 CA9xx AI 建议层，
  只发评论/清单，不拦合并。这条由 `tests/run_tests.py` 的不变量钉着（防止有人把报告改成 error）。

## 三、单人阶段：pre-commit 钩子

`canonlint init` 会在世界仓库里装 `.git/hooks/pre-commit`（前提是那里已经有 `.git`；
先 `git init` 再跑一次 init 即可）：

```sh
#!/bin/sh
<exe> "$(git rev-parse --show-toplevel)" || exit 1
```

**注意**：`init` 装的钩子**不带 `--strict`**——它只拦 error，不拦 warning。
要连 warning 一起拦，在 `|| exit 1` 前面自己加 `--strict`。

## 四、本工具仓库自己的协作机制

- **main 受保护**：只能走 PR；四个检查必须绿；分支必须先同步到最新 main。
- **四个检查名**（分支保护按名字要求）：`canonlint (3.12)` / `canonlint (3.14)` /
  `classlint (3.12)` / `classlint (3.14)`。
- **合并方式**：Merge（不用 squash / rebase——保留每个提交作为可整体回滚的单元）。
- **CODEOWNERS**：目前只有仓库所有者 `@sliensnomen`。「Require review from Code Owners」是**刻意关闭**的：
  GitHub 不允许自己 approve 自己的 PR，开着等于把自己的 PR 锁死。等有第二位 code owner 再开。
- **该保护什么**：本工具仓库保护 `/store/`、`/world.schema.json`、`/tests/`、`/.github/workflows/`；
  世界数据仓库保护 `/entries/`、`/CONSTITUTION.md`、`/works/`（作品层是计划中的事）。

上手步骤（clone → 基线 → 菜谱 → PR）见 [../CONTRIBUTING.md](../CONTRIBUTING.md)。
