# WGP 协作层：git 工作流与协议状态机的映射

协议不规定权限模型（审计中立性条款，§6.2），本文件是**参考实现**的协作层做法：
全部用 forge（GitHub/Gitea）的现成机制拼装，零自研。

## 角色

| 角色 | 能做什么 | forge 机制 |
|---|---|---|
| 贡献者 | 开分支、写 draft、发 PR | 任何人 |
| 评审组 | approve PR、执行升格/降级/恢复 | CODEOWNERS + 分支保护 |
| 创始人（BDFL） | 最终裁决、宪章修订 | main 分支保护规则 |

## 状态机 ↔ git 操作

| 协议动作 | git 操作 |
|---|---|
| 新建提案（draft） | 分支写条目（`entries/{type}/`）→ PR |
| draft → trial | PR 改 `status`，跑过一场桌后评审组合并 |
| trial → canon | PR 改 `status`；CODEOWNERS 强制评审组 approve，CI 必须绿 |
| canon → archived | 降级 PR：必须同时填 `superseded_by`，CI 自动贴 CA504 下游清单作为复核工单 |
| archived → trial/canon | 恢复 PR，默认重走升格；快速通道由本仓库宪章声明 |
| 矛盾标注 | PR 给双方条目加 `conflicts_with`，不阻塞任何合并 |

**目录约定（协议 v1.0.1）：** `entries/{type}/` 是唯一条目位置。状态只认 frontmatter，
不做目录隔离——升格保护靠 CODEOWNERS 对 `entries/` 的评审要求，不靠路径。

## CI 门禁（见 .github/workflows/canonlint.yml）

1. `canonlint --strict`：error 和 warning 都拦——红叉即拒合并；
2. CA504 影响报告：自动评论"本次变更的下游待复核清单"，不拦截；
3. CA9xx（AI 建议层，未来）：只发评论，永不拦截。

## 单人阶段（现在）

不需要 forge：本地 `git init` + pre-commit 钩子即可：

```bash
# .git/hooks/pre-commit（世界仓库里，不是 canonlint 工具仓库）
#!/bin/sh
python3 /path/to/canonlint.py "$(git rev-parse --show-toplevel)" --strict || exit 1
```

人等多了再把仓库推上 Gitea/GitHub，打开分支保护和 CODEOWNERS——
协议一个字不用改，这就是"治理密度是地方事务"的意思。
