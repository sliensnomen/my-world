# 1.4 事件优先卡模型 · 发行计划（草案）

**日期：2026-11-24 ｜ 状态：草案（待拍板） ｜ 读者：作者 + 实现者**

> **前身**：[2.0 第一个发行版计划](2.0-release-plan.md)（2026-11-24 废弃）。
> 作者否决「事件唯一、实体卡消亡」的 2.0 本体论；1.4 改为「事件卡最高、卡保留」。
> 2.0 的 `spine/`、迁移、attic、LLM 抽取基准不再投入，只留作历史证据。

## 0. 先读这一节

2026-11-24 的对谈把方向改成了三件事：

1. **事件卡是作者主要写作的**；实体卡是设定声明，像编程里的「先声明后使用」。
2. **实体卡不消失**：可以独立创建、可以直接编辑；没有被任何事件引用时给 warning，
   事件引用一个不存在的实体时报 error（后者已是 CA401 的现状）。
3. **不做 2.0 的破坏性迁移**：不换 `type: transfer`、不做 `type: import` 期初事件、
   不把实体卡迁进 `attic/`、不做 LLM 抽取基准；先出普通 Web 版，优质前端后置。

一句话：**1.4 不是换本体，是把 1.x 已有的「事件流水」从设计底座提升为作者主路径。**

版本口径需要先说明：**1.4 是产品/发行版号**；本次新增一条 CA warning，协议从 1.32
按 §9.1 升到 1.34（不能把协议号写成 1.4，数字会倒挂）。

## 1. 三种模型，避免再走岔

| | 1.x 现状 | 2.0（已废弃） | 1.4（本计划） |
|---|---|---|---|
| 世界最小单位 | 条目卡（实体卡 / 事件卡） | 事件 | 事件卡（主写作面）+ 实体卡（声明） |
| 实体 | 实体卡 | 事件投影，无卡 | 实体卡保留，可独立建 |
| 事件写法 | `type: event` + `event_kind` | `type: transfer` | 保持 `type: event` + `event_kind` |
| 当前状态 | 卡断言 + 流水，CA704/709/712 对账 | 纯事件投影 | 卡断言 + 流水，事件流水优先 |
| 期初状态 | 卡上断言 | `type: import` 事件 | 卡断言优先；import 事件作补充 |
| 目录 | `entries/` | `spine/` | 同一个 `entries/` |
| 迁移 | 无 | 实体卡单向迁走 | 无迁移，旧世界直接可用 |
| 审计 | CA4xx + CA7xx + classlint | 事件结构 + 投影 | CA4xx + CA7xx + classlint，保留全栈 |
| Web | 五视图，记账是附属表单 | 只做 CLI | **普通 Web 版：事件时间线为主** |
| 版本性质 | 1.x 现行 | 破坏性 2.0 | 1.4 兼容大更新 |

「最高等」在本计划里的定义是：**事件卡是作者打开工具后首先写、首先看的东西，
是历史的主叙述；它不是唯一的事实来源。** 实体卡仍然是声明的来源、当前结论的断言处，
也是事件引用的目标。两者冲突时按 1.x D3 对账，不搞「事件自动改写一切」。

## 3. 非目标（1.4 明确不做）

- 不做 `type: transfer` 新事件格式；不迁移现有 65 张事件卡。
- 不做 `type: import` 期初事件；不把实体卡断言搬进事件。
- 不做 `attic/1.x/`、不做 main 切换、不做 1.x 维护分支。
- 不做 LLM 抽取、确认流、precision/recall 对账基准。
- 不重写 classlint / econ / serve；不砍现有五视图，只调整主路径。
- 不做完整 IDE：不做 LSP、不做 Monaco、不做 VS Code 扩展；1.4 的「像 IDE」指
  诊断、补全、跳转、错误定位，先落在现有零依赖 Web 上。
- 不开第二条写通道：Web 写卡仍走 `store/` 的同一套审计与回滚。

## 4. 模型约束

### 4.1 事件卡

- 仍是 `type: event` 的卡，`event_kind` 给十二种之一（或 `x-` 实验值）。
- 腿：`by` / `to` / `object` / `from` / `result`；时间：`when` / `when_sort`。
- 治理字段：`status`（draft/trial/canon/archived）与 `load_bearing`。
- 关系：允许 `canon_refs` / `depends_on` / `conflicts_with`；`owns` / `custody_of` /
  `member_of` 仍只写在实体卡上，作为当前结论断言。
- 正文是作者叙事；事件卡不是「结构化表单的附件」，正文与腿同权。

### 4.2 实体卡

- 是声明，也是「当前结论」的断言处；`id` 是事件引用的锚点。
- 可以没有事件，但会收到「未被事件引用」warning。
- 可以直接编辑；事件按 `id` 引用，不拷贝实体内容。
- 不因 1.4 被降级为只读缓存。

### 4.3 引用与诊断

- 事件腿、事件关系、实体关系、断言里的 id 必须能解析；缺失 = CA401 error。
- 「未被事件引用」统计事件腿（`by/to/object/from/result`）与事件卡 `canon_refs` 的引用；
  实体关系与正文 mention 不计入，避免误报。
- 编辑器把缺失引用显示为 error，把未被引用显示为 warning；没有 quick fix。

### 4.4 当前状态

沿用 1.x D3：

- 卡上 `owns` / `custody_of` / `member_of` 是作者对当前结论的断言；
- 事件是变化；派生状态由流水推出；
- 流水覆盖不到的轴才由断言兜底；
- 有流水时断言必须与最终流水一致（CA704/709/712）。
- 冲突时事件赢，但「赢」的方式是报 error 让作者改卡；工具不静默改写卡面。

## 5. 1.4 交付范围

### 5.1 模型与规则

1. 事件卡 `status` / `load_bearing` 的读写与审计口径（schema 已允许，补测试与文档）。
2. 「未被事件引用」：新增 CA warning（协议 1.34；编号实现时按 §6.3 顺延），统计事件腿
   与事件 `canon_refs`；旧世界新增 warning 需在快照中显式接受。
3. 缺引用 error 的回归：CA401 已覆盖事件腿；补显式用例，确保不会被静默吞掉。
4. 事件卡关系白名单：`canon_refs` / `depends_on` / `conflicts_with` 可用；
   断言类字段不在事件卡上生效。
5. 旧世界兼容：原有 9 个 `tests/world-*` 一条不红；新增 `world-event-first` 独立验收。

### 5.2 普通 Web 版

目标：作者打开就能写事件，不需要读 CLI 文档。

1. **默认视图 = 事件时间线**：按 `when_sort` / `when` 排序，按 `event_kind`、`status`、
   涉及实体筛选；每条显示腿摘要与 findings。
2. **事件编辑器**：新建与编辑事件卡；结构化字段 + 正文；`status` / `load_bearing`；
   保存前本地提示缺腿；保存后服务端审，红则回滚。
3. **实体页**：显示声明、当前断言、被哪些事件引用；未被引用显示 warning 徽标；
   可新建/编辑实体卡。
4. **诊断面板**：error/warning 列表，点击跳到事件或实体；显示规则号与消息；
   不做 quick fix（按拍板）。
5. **零依赖零构建**：仍用 `web/index.html` + 原生 JS；不引 React/Vue/CodeMirror。
6. **只读默认**：`--writable` 才显示写入口；写请求同源 + JSON + 可选 token。

### 5.3 API / CLI

- 现有 `POST /api/entry`（写卡）、`POST /api/event`（记账）、`POST /api/status`

- 不新增 `canonlint` 子命令，除非 Web 需要且不能复用现有入口。

## 7. 验收

1. **旧世界默认不新增 error**：`tests/world-*` 十个世界在默认模式下不新增 error；
   新增 CA warning 会改变快照，`--strict` 下还会变红，需逐条核对并显式更新基线。
2. **事件优先可写**：在 `tests/world-ledger` 上启动 `--writable`，默认看到事件时间线；
   新建一笔 `transfer` 事件（引用已有实体）→ 201，时间线出现，审计绿。
3. **缺引用报错**：新建事件引用不存在的 id → 422，回滚，错误信息含 CA401；
   手动建实体卡后重试成功。
4. **未引用 warning**：新建一张不被任何事件引用的实体卡 → 实体页显示「未在事件中引用」；
   `canonlint check` 与诊断面板都可见（CA warning，协议 1.34）。
5. **编辑不拷贝**：改实体卡标题/状态，引用它的事件页立即反映；事件文件不变。
6. **当前状态**：`canonlint ledger` 仍按 D3 输出；事件与断言冲突时 CA704/709/712 报出。
7. **文档一致**：`tests/test_docs.py` 全过；2.0 计划/CHARTER/spine 状态为历史/冻结；
   README 不再说「事件唯一、实体卡消亡」；协议版本号为 1.34。
8. **econ 食物链**：人口 500,000 × 人均 0.6 kg → 消耗 300,000 kg；供给 200,000 kg
   → 报缺口 100,000 kg 的 warning，公式与单位可见；推导值不写回卡。

### 8.1 econ 推导（1.4 食物链）

作者定比例，工具做推导和对账；不是工具替作者定现实值。

已拍板：

- **E0 A**：1.4 只做食物一条链。
- **E1 A**：推导只进报告/Web，不写回卡。
- **E2 A**：先全世界一组比例。
- **E3 A（复核改为 warning）**：推导值与声明不一致报 warning；补 `grain_import` 或
  `justification` 后放行（CA602 先例），不允许静默忽略。
- **E4 B**：比例放世界根 `econ.yaml` 的 `params`；`figures` 仍按现有卡字段，不搬。

三层：

| 层 | 谁写 | 例 |
|---|---|---|
| 公理 `params` | 作者 | `food_per_person_day: 0.6 kg_grain/person/day` |
| 输入 `figures` | 作者 | `population: 500000 persons` |
| 推导 `derived` | 工具 | `消耗 = 1,250,000 kg_grain/day` |

规则：

- 知道两个就能推第三个；三个都写做 tolerance 对账，不要求作者填满。
- 缺比例/缺输入跳过（缺数据不报错）；比例非法（负值、单位不成立）error。
- 不一致 warning；作者补 `grain_import` 或 `justification` 后放行，不允许静默忽略。
- 比例是 canon：带 `unit` / `source` / `scope`；工具只提供示例预设，不写死现实值。
- 推导值默认不写回卡；要固化加 `derived: true` + 来源，另立拍板。
- 与 classlint 的 `demand` / `population` / `surplus` 共用一个参数注册表：econ 管数值，
  classlint 管结构；边界实现时定。

首条链：`population × food_per_person_day` → 消耗；对比 `grain_supply`；
缺口 = 供给 − 消耗。验收里的 350,000 kg 就是这条链的输出。
