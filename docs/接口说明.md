# 接口说明（`serve.py`）

HTTP 接口：把世界数据交给前端；`--writable` 时还能写卡、记账、升格/降级。
**它不是界面，也不做判定** —— 判定在 `canonlint.py` 里，写入口只是把「写完即审、红则回滚」的
pre-commit 纪律延伸到 HTTP。默认只读。

## 起服务

```bash
python3 serve.py tests/world-arrakis                 # 默认 127.0.0.1:8000
python3 serve.py ~/worlds/grey-harbor --port 9000 --pack econ
python3 serve.py ~/worlds/grey-harbor --writable      # 开放 POST 写入口（默认只读）
python3 serve.py --port 0                            # 让系统挑空端口，启动时会打印真实地址
```

- Python 自带，**不用装任何东西、不联网**。
- 默认只监听本机（要对外才加 `--host 0.0.0.0`）。
- **每次请求都重新读盘**：改完 Markdown 刷新页面就是新数据；不该被缓存的都不缓存。
- `--writable` 下的写请求**串行化**（进程内一把锁）：写卡后的审计回滚是「写卡 → 全库审 → 红就删」，
  两个请求交错会互删新卡。
- 写请求只接受**同源页面**发来的 `application/json`（`Origin` 的 netloc 必须等于 `Host`；
  没有 `Origin` 的 `curl`/脚本放行；`Content-Type` 不是 JSON 给 `415`）。原因见下面「跨源写」。

## 路由

| 路由 | 给什么 | 备注 |
|---|---|---|
| `GET /` | 一页说明（条目/边/错误数量 + 路由表） | 给人和自检用，不是界面 |
| `GET /api/health` | `{ok, world, protocol_version, contract_version, counts, writable, required_legs}` | 存活与版本号；`writable` 告诉前端能不能显示写入表单 |
| `GET /api/world` | 整个世界（条目 + 边 + 词表 + findings + reports + ledger 派生状态） | **与 `canonlint export` 的数据完全一致**（有测试钉死） |
| `GET /api/entry/<id>` | `{protocol_version, contract_version, entry, relations}`：单个条目 + 进边和出边 | 查不到给 `404` |
| `GET /api/raw/<path>` | 世界目录里的原始文件 | 只读；不能穿越出世界目录 |
| `GET /web/...` | 仓库根下的 `web/`（与 `serve.py` 同级）里的前端文件 | 同源，省掉 CORS |
| `POST /api/entry` | 写一张卡（JSON：`{type, title, id?, author?, ...字段}`） | **仅 `--writable` 时可用**；`id` 省略时自动起名（`<type>-<序号>`，中文标题不再 400）；写完即审，红则 `422` 并只回滚本次请求建的文件；成功 `201 {ok, id}` 返回**真实 id** |
| `POST /api/event` | 记一笔流水（JSON：`{event_kind, id?, title?, when?, when_sort?, by?, to?, object?, from?, result?}`） | 同上；坏 `event_kind` 给 `400`，id 撞车给 `409`；`event_kind` 接受词表值或 `x-` 实验值 |
| `POST /api/status` | 升格/降级（JSON：`{id, status?, superseded_by?}`） | 同上；行级写入，写完即审、红则**原子**回滚；`id`/`status` 类型不合法给 `400` |

## 例子

```bash
curl -s localhost:8000/api/health
curl -s localhost:8000/api/world | python3 -m json.tool | head -40
curl -s localhost:8000/api/entry/arrakis
curl -s localhost:8000/api/raw/entries/arrakis.md

# 写入口（需要 --writable；脚本没有 Origin，是被放行的）
curl -s -X POST localhost:8000/api/entry \
  -H 'Content-Type: application/json' \
  -d '{"type":"location","title":"新港","id":"new-port"}'
curl -s -X POST localhost:8000/api/event \
  -H 'Content-Type: application/json' \
  -d '{"event_kind":"transfer","when":"元年","when_sort":1,"by":["a"],"to":["b"],"object":["relic"]}'
curl -s -X POST localhost:8000/api/status \
  -H 'Content-Type: application/json' \
  -d '{"id":"new-port","status":"trial"}'
```

## 规矩（都有测试守着）

- **默认只读**：`POST` / `PUT` / `DELETE` / `PATCH` → `405`；`--writable` 只开三个 POST 路由，
  `PUT`/`DELETE`/`PATCH` 仍是 `405`。
- **跨源写要挡住**：`text/plain` 的 simple POST 不触发预检，光靠 CORS 响应头挡不住任意网页替用户写卡——
  所以写请求校验同源 `Origin` + `application/json`（`403` / `415`）。`OPTIONS` 在可写模式下列出 `POST`
  并回显请求的 `Origin`。
- **写后审计与读路径同口径**：`--pack econ` 等扩展包在读、写、CLI 三条路径上应用同一份
  `extra_known`/`packs`——不允许「读时合法、写时非法」。
- **坏请求不制造断连**：非法 JSON / 非字符串 `id`/`title` / 超大请求体分别给 `400`/`400`/`413`；
  处理器里没预料到的异常变成 JSON `500`。
- **不穿越**：`/api/raw/../canonlint.py` → `404`。
- **不露工具自己的东西**：隐藏文件与目录（`canonlint init` 会在世界目录里建 `.git`，里面有配置、钩子、索引）→ `404`。它们躺在「世界目录内」，所以只查穿越挡不住。
- **路径里的 NUL 字节** → `400`（不是断连）。`Path.resolve()` 遇到 NUL 会抛异常，以前没人接，请求方拿到的是空响应——分不清「没有这个文件」与「接口挂了」。
- **`/web/` 只取 `web/` 里的文件**：`/web/../` 折返、`..%2f` 编码写法一律 `404`；目录不存在时提示「把前端文件放进 `web/`」（仓库根、与 `serve.py` 同级）。
- **不漏主机路径**：数据里只有世界仓库内的相对路径。
- **同一份数据两次请求字节一致**（没有时间戳、没有随机）。
- GET 响应头带 `Access-Control-Allow-Origin: *`，`Cache-Control: no-store`；写模式下的 `OPTIONS`
  回显请求的 `Origin` 并带 `Vary: Origin`（不把写权限广播成 `*`）。
- 中文 id 记得 URL 编码（浏览器 `fetch` 与 `curl` 一般会自己处理）。

## 坏文件怎么办

读不出来的文件**也会出现在 `entries[]` 里**：`id` 是 `null`、`path` 指到它、`parse_error` 写着原因。
`/api/entry/<id>` 查不到它（它没有 id）——前端按 `path` 找它、灰着显示就行。

## 把前端放进来

把前端文件放进仓库根下的 `web/`（与 `serve.py` 同级），然后开 `http://127.0.0.1:8000/web/index.html`：
和接口同源，不用管 CORS。`wgp-client.js`（仓库根）可以直接拷进去一起用。

## 解析器（`wgp-client.js`）

```html
<script src="/web/wgp-client.js"></script>
<script>
  WGP.load("/api/world").then(function (world) {
    var mm = world.mindmap("bene-gesserit");  // {center, branches:[{type, items:[…]}]}
    world.entries;      // 全部条目（补过默认值）
    world.neighbors("arrakis");  // 一个条目的进边 + 出边
    world.dangling;     // 指不到人的边（已标原因）
    world.broken;       // 读不出来的文件
    console.log(mm);
  });
</script>
```

它只做四件事：补默认值（缺字段、坏文件、重名）、建索引、给 `mindmap()`、标出指不到人的边。
**关系名原样用，不翻译、不判断**；字段名是两边的合同，不要自己加语义。
