## 6. 结论

**verdict: `needs_revision`**

六套全绿，但绿并不覆盖本次改动的中心承诺。`PROTOCOL.md:38` 第 18 条写的
「边图含顺序与形状问题必须逐条相同，例外只许是登记的那处口径差」在**注解取值写坏**、
**搬家缺 critical**、**x- 扩展属性**三类输入上不成立，而新锁的形状表恰好不含这些形状。
这不是新引入的运行时崩溃，而是「刚宣布的同判不变量还没落地，锁先宣布它落地了」——
按本仓库的分类，正是头号公敌的测试面版本：**锁看起来在钉，实际钉不到。**

修复顺序建议：

1. 统一取值错误的建边行为（`store/model.py:346-354` vs `:260-265`），对齐文案；
2. 补 1.1 的 6 个形状进锁，并放宽豁免谓词到 `derives_legitimacy_from`；
3. 补 CL106 锁（legacy 写法 → CL106 + PE 判定逐条一致）；
4. 补 `kind` 键收紧与契约解析器 id 校验两把最小锁。
