## 0. 结论摘要

写入路径的核心承诺是「文本级插入、diff 小到能被人评审」（`store/write.py:3-4`），
但实测：**插入器不解析 YAML，重写器不保留字节**。三种合法输入形态会让 `link` 在报「已连线」
的同时，把边写丢或把卡片写坏（B1）；`new` 会把用户给的标题/署名原样拼进 YAML，
其中 `#` 形态是无声丢字（B2）。另外深嵌套 frontmatter 会让 `yaml.safe_load` 抛
`RecursionError` 逃出 `except yaml.YAMLError`，整个世界的审计直接 traceback（H1）。

「没变红的锁等于没有锁」：以上每一条都**没有任何测试覆盖**（`grep` 证据见各条），
所以六套绿与这些缺陷并不矛盾。

## 1. Blocker

### 1.1 `link` 的文本级插入不是 YAML 感知：三种合法形态下写坏卡片或写丢边，且报「已连线」

```
[严重度: blocker]
文件:store/write.py:185-206（_insert_dep_text，正则逐行扫 frontmatter）
     store/write.py:236-237（去重只查已建模的边，不看文本形态）
     store/parse.py:234（重复键 last-wins 是 PyYAML 默认行为，全仓无一处报告）
断言：_insert_dep_text 用 ^depends_on: 正则找「depends_on 那一行」，然后按「空格/横杠开头」
      判序列边界、按固定两空格缩进生成新条目。它对「找到的行到底是不是那个键」「已有条目是什么缩进」
      「这个键出现了几次」一无所知，于是：
      (a) 零缩进序列（与键同列，YAML 合法）被插入成非法缩进 → 整卡解析失败；
      (b) 重复键时插到被覆盖的那一个上 → 边在解析结果里根本不存在，全链路零报告；
      (c) 多行双引号标量里的 depends_on: 行被当成键 → 标题字符串被插进依赖块，边不存在。
      三种形态下 link 都 rc=0 并打印「已连线」。
```

**证据 (a)：零缩进序列 → 卡片被写坏，link 仍报成功。** 造一张合法卡（`depends_on:` 的条目
与键同列，这是 YAML 允许的写法）再跑一次 link：

```yaml
# 写入前（python3 -c 探针构造，store.parse_entry 读出 parse_error=None，edges=['existing']）
depends_on:
- id: existing
  kind: fiscal
  critical: true
```

```
$ python3 canonlint.py link --root w a b --kind fiscal
已连线: a --fiscal--> b                       ← rc=0，宣称成功
```

```yaml
# 写入后（文件的这一节）
depends_on:
- id: existing
  kind: fiscal
  critical: true
  - id: b                ← 固定两空格缩进，插进了已有条目的映射里
    kind: fiscal
    critical: false
```

```
$ python3 canonlint.py w
[CA100] error   entries/a.md: frontmatter YAML 解析失败: while parsing a block mapping
  in "<unicode string>", line 11, column 3:
    - id: existing
      ^
expected <block end>, but found '-'
  in "<unicode string>", line 14, column 3:
      - id: b
      ^
```

`store.parse_entry` 对写后文件的读取结果：`parse_error` 非空、`relations == []`——
不仅新边没进去，**原有那条边也随整卡消失**。下一次审计才亮 CA100，但那时 link 的成功消息已经撒了谎。
（对照：两空格缩进的序列形态插入正确——所以这不是「不支持 block list」，是「只支持一种缩进」。）

**证据 (b)：重复键 → 边写进被覆盖的键，全链路零报告。**

```yaml
# 写入前
depends_on: []
z-sep: 1
depends_on: []
```

```
$ python3 canonlint.py link --root w a b --kind fiscal
已连线: a --fiscal--> b                       ← rc=0
```

```yaml
# 写入后（第一处被改，第二处仍是 []）
depends_on:
  - id: b
    kind: fiscal
    critical: false
z-sep: 1
depends_on: []
```

```
parse_entry(...).meta['depends_on'] == []     ← PyYAML 重复键 last-wins，边不存在
parse_entry(...).relations == []
$ python3 canonlint.py w
[CA106] error   entries/a.md: 未定义字段 `z-sep`（扩展字段须 x- 前缀）   ← 没有一条规则提重复键
```

**证据 (c)：多行双引号标量 → 标题被插进依赖块，边不存在。**

```yaml
# 写入前，store.parse_entry 读出 title='hello depends_on: [] world'
title: "hello
depends_on: []
world"
...
depends_on: []
```

```
$ python3 canonlint.py link --root w a b --kind fiscal
已连线: a --fiscal--> b                       ← rc=0
```

```yaml
# 写入后
title: "hello
depends_on:
  - id: b
    kind: fiscal
    critical: false
world"
```

```
parse_entry(...).meta['title'] == 'hello depends_on: - id: b kind: fiscal critical: false world'
parse_entry(...).relations == []
```

三种形态的共同后果与 (b) 相同：**用户数据被改、目标操作没发生、没有任何一处输出提到这件事**。

**修法（具体到函数）：**
1. `_insert_dep_text` 不要在原文行上做正则判断，改用 `yaml.compose(fm_text)` 拿到节点流，
   找到**最后一个**顶层 `depends_on` 键（与解析器 last-wins 一致），用它的 `start_mark`/`end_mark`
   定位到真实行号再插；发现同名键出现多次时直接拒绝（返回 None → 让 cmd_link 报
   「depends_on 键重复，请先手工修」），因为重复键本身就是坏形态。
2. 已有条目的缩进从**已有条目行**推导（`re.match(r"(\s*)- ", line)` 取前缀），
   零缩进序列就按零缩进插；没有条目时才用当前的两空格。
3. 只要 `yaml.compose` 解析不了（多行标量那类形态会正常通过 compose），
   就退回「拒绝并让人手改」，宁可 rc=2 也不能猜。

### 1.2 `new` 把 title/author 原样拼进 YAML：`#` 之后无声丢字，冒号直接产出坏卡

```
[严重度: blocker]
文件:store/write.py:156-158（meta_lines 里 f"title: {title}" / f"author: {author}" 裸拼）
断言：title 与 author 是用户输入，未做任何 YAML 转义。特殊字符会改变语义或破坏文件，
      而 new 对全部形态都打印「已建卡」并 rc=0。
证据：九种标题 + 两种署名逐一走 canonlint new，再用 store.parse_entry 读回：
```

```
title='foo: bar'      rc=0  parsed <missing>     parse_error='mapping values are not allowed here'
title='*star'         rc=0  parsed <missing>     parse_error="found undefined alias 'star'"
title='a: & b'        rc=0  parsed <missing>     parse_error='mapping values are not allowed here'
title='multi\nline'   rc=0  parsed <missing>     parse_error='while scanning a simple key'
author='a: b'         rc=0  parsed <missing>     parse_error='mapping values are not allowed here'
title='foo # bar'     rc=0  parsed 'foo'         parse_error=None   ← 无声丢字（# 之后全没了）
author='anon # tag'   rc=0  parsed 'anon'        parse_error=None   ← 署名同样无声丢字
title='  padded  '    rc=0  parsed 'padded'      parse_error=None   ← 首尾空白被无声吞掉
title='42'            rc=0  parsed 42（int）     parse_error=None   ← 字符串被无声改成数字
title='null'          rc=0  parsed None          parse_error=None
title='[bracket]'     rc=0  parsed ['bracket']   parse_error=None   ← 字符串变成列表
```

两组形态：前五行（含作者 `a: b`）在**下一次审计**才以 CA100 出现——但写入这一刻的输出是
「已建卡」，没有一句提醒；后六行连审计都不报错，**写进去的和读回来的不是同一个值**（丢字、
吞空白、换类型），却完全无声。

```
$ grep -n "title" tests/test_store.py | grep -c "#"    → 0   （没有锁）
```

**修法：** `cmd_new` 里把 `f"title: {title}"` / `f"author: {author}"` 换成
`f"title: {json.dumps(title, ensure_ascii=False)}"`（JSON 字符串是合法 YAML 双引号标量），
author 同理；或对这两个标量走 `yaml.safe_dump`。加锁：造一张 `title: foo # bar` 的卡，
断言 parse 回来的 title 逐字等于输入。

## 2. High

### 2.1 深嵌套 frontmatter → `RecursionError` 逃出 except，整个世界的审计崩溃

```
[严重度: high]
文件:store/parse.py:233-237（read_frontmatter 只捕 yaml.YAMLError）
断言：yaml.safe_load 对深嵌套流式集合抛 RecursionError，它不是 YAMLError；
      实测 n=400 层正常、n=500 层崩溃（本机 3.14.8，阈值随递归上限浮动，机制不变）；
      read_frontmatter 的 docstring 写着「失败也是一个结果（parse_error），不是异常」——
      实际是一个卡片把整场审计打成 traceback，且报错里没有文件名。
证据：
```

```
# 造一张卡：title: 后跟 500 个 [ 加 500 个 ]
$ python3 canonlint.py crashworld
... File "yaml/composer.py", line 82, in compose_node ...
RecursionError: maximum recursion depth exceeded        ← 无文件名，无 CA100
$ echo $?   → 1
```

```
# 同一张卡喂给 classlint：
$ python3 classlint/classlint.py check econ
RecursionError: maximum recursion depth exceeded        ← 同样逃逸
```

后果不止审计：`cmd_link`/`cmd_new` 都先 `collect(root)`，同一张卡会让**写入命令**也崩。

### 2.2 `link` 吞掉正文行首空白：4 空格缩进的正文首行被去缩进（markdown 里这是代码块）

```
[严重度: high]
文件:store/parse.py:27（FRONTMATTER_RE 尾部 "\s*\n?" 贪婪，能吃掉闭合围栏之后的全部空白）
     store/write.py:256（重写时不复用原围栏字节：f"---\n{new_fm}\n---\n" + body[m.end():]）
断言：m.end() 落在闭合围栏后的全部空白之后，重写又用规范化的围栏把正文接回去，
      于是「围栏与正文第一个非空白字符之间的所有字节」被静默删除。
证据（写入前 → link 后，取 ai_assisted 之后的原始字节）：
```

```
before: 'e\n---\n\n    code block\nmore\n'
after : 'e\n---\ncode block\nmore\n'     ← 正文首行的 4 空格没了：markdown 代码块没了

before: 'e\n---\n\n\tTabbed\n'
after : 'e\n---\nTabbed\n'               ← 制表符同样被吞

before: 'e\n---\n\nBODY'                 ← 无末尾换行
after : 'e\n---\nBODY'                   ← body 本身保留，但空行被吞

开场围栏后一个空行：before '---\n\nid: a' → after '---\nid: a'
开场围栏行尾一个空格：before '--- \nid:' → after '---\nid:'
闭合围栏行尾空格：   before '--- \n\n\nBODY' → after '---\nBODY'
```

普通 `new` 产出的卡恰好带着两个空行（`new` → `link` 的文档化工作流），所以这是
**每一步都要复现**的字节变化，`store/write.py:4` 的「diff 小到能被人评审」不成立。
（正文长度统计用 `clean_body` 也会差异，因为它对 body 做同样的正则切分——正文语义在
「写回」这一刻才真正被改。）

```
$ grep -rn "FRONTMATTER_RE" tests/ classlint/tests/
tests/test_schema.py:83（测试自己另有一份正则，语义不同）; tests/test_store.py:674（只锁「两引擎共用」）
→ 没有任何测试锁住 link 后正文/围栏字节的保留
```

**修法：** 重写时不做规范化拼接：
`text = body[:m.start(1)] + new_fm + body[m.end(1):]`——`m.start(1)`/`m.end(1)` 之间的
原始围栏字节（含 `--- ` 行尾空格、围栏后空行）原样保留，只替换 group(1) 的 frontmatter。

## 3. Medium

### 3.1 `link` 静默改写只读文件，并把权限 0644/0755 改成 0600

```
[严重度: medium]
文件:store/write.py:24-36（_atomic_write：mkstemp 建 0600 临时文件 + os.replace，不保留 mode）
断言：Unix 允许「目录可写」时替换只读文件，所以 0444 的卡片被照样替换、无声；
      任何经过 link 的卡片模式统一变成 0600（甲 0644 → 0600，0755 → 0600）。
证据：
```

```
mode 644 -> 0o600 | rc 0
mode 755 -> 0o600 | rc 0
read-only file: rc 0 | 已连线: a --fiscal--> b | mode now 0o600 | edge written: True
```

**修法：** `_atomic_write` 里 `os.fchmod(fd, path.stat().st_mode & 0o7777)`（先取旧模式，
新文件无旧模式时用 0o644 & ~umask），并考虑对只读文件先拒绝（`os.access(path, os.W_OK)` 不满足时报错）。

### 3.2 `link` 把符号链接卡片替换成普通文件（硬链接同理断链）

```
[严重度: medium]
文件:store/write.py:256（os.replace(tmp, e.path) 对链接路径替换的是链接本身）
断言：entries/ 下指向世界外的符号链接卡片会被扫描（iter_entry_paths 收），但 link 写入时
      os.replace 把链接替换成普通文件：链接拓扑无声破坏，世界外的目标保持旧内容，两份分叉。
证据：
```

```
collected: True                （链接卡确实在世界里被扫描、被引用）
entry id via symlink: zzz
$ canonlint.py link --root w zzz b --kind fiscal   → rc 0 已连线
still symlink? False           ← 链接没了
outside target got edge? False ← 世界外目标没改
world copy got edge? True
```

（硬链接：`inode a: 57816 → 57818`，世界外的硬链接副本留在旧内容。os.replace 的固有语义，
一并记在这里。）

**修法：** `_atomic_write` 前 `path = path.resolve()` 写穿链接目标；或检测 `path.is_symlink()`
时改成直接写（`write_text`）并接受非原子；至少要在替换链接时报一声。

### 3.3 `link` 把整份 CRLF / CR 文件静默转成 LF

```
[严重度: medium]
文件:store/write.py:243（read_text(encoding="utf-8") 通用换行，读进来就没了 \r）
     store/write.py:256（写回 LF）
断言：read_text 默认 newline=None，CRLF 与裸 CR 在内存里都被换成 LF，写回时不还原。
      一次 link = 一次全文件行尾归一，diff 里全是行尾变化。
证据：
```

```
before after-fence: 'e\r\n---\r\n\r\n\r\nBODY\r\n'
after  after-fence: 'e\n---\nBODY\n'          ← 整个文件的 \r 全没了

# 解析侧同样如此（CR-only 文件 read_text 后能被正常解析）：
CR-only raw bytes: b'---\rid: cr\rtitle: CR'
CR-only parsed: id=cr body='BODYLINE\n' parse_error=None
```

写回 LF 也许可以被当作一种「归一化」，但它是无声的：没有提示、没有文档、没有锁；
Git autocrlf 环境里等于每次 link 全文件重写。

**修法：** `read_bytes().decode("utf-8")` 取代 read_text（BOM 由现有 `\ufeff` 分支处理），
保留原行尾；要归一化就显式起步并写进文档。

## 4. Low

6. **扫描对 README 的处理前后不一致**：根 README 跳过（`store/layout.py:37`），
   `entries/README.md` 与扁平模式的根 README 都被当条目 → CA100 假阳性
   （实测 `[CA100] entries/README.md: 缺少 frontmatter`；扁平模式同样报 README.md）。
7. **规范形卡片无法用 `link` 写边**：没有旧 `depends_on` 键的卡一律 rc=2

8. **`.git` 是文件时（linked worktree）`init` 静默装不上钩子**：`is_dir()` 为假 →

10. **解析层对重复键零报告**：不经过 link 的重复键卡（`depends_on` 之外同理）静默
    last-wins，`[CA106]` 只报未定义字段。见 1.1(b) 的证据。

## 5. 变形矩阵（每格给结论）

## 6. 文件系统边角

| 场景 | 实测行为 | 结论 |
|---|---|---|
| 只读文件 0444 | 照常替换，模式变 0600 | 3.1 |
| 只读目录 0555 | PermissionError traceback | L1 |
| 符号链接卡（指向世界外） | 被扫描；`link` 后链接变普通文件 | 3.2 |
| 硬链接 | os.replace 断链，外部副本旧内容 | 3.2 |
| 悬空符号链接占位 | `new` 写到世界外 | L4 |
| 并发两个 `link` | 丢一条边，两个都报成功 | L2 |
| SIGKILL 中途 | 目标文件安全（旧或新），遗留 `.canonlint-*.tmp` | L5 |
| 符号链接目录（含环） | `rglob` 不跟进（3.12 与 3.14 均不留环、不悬挂） | 无问题 |
| 大小写不敏感 FS | ext4 上无法验证 | 见「没能验证」 |

## 7. 往返与幂等

- `init` 重跑：CONSTITUTION.md 用户修改保留，钩子相同则不重写；零字节变化。
- `new` 撞已有 id：rc=1，原文件字节不变（有锁）。
- `link` 同一条边第二次：rc=0「边已存在」，零字节变化；但**不含**它对正文的隐形改动
  （空行/缩进/行尾在第一次运行时已被吞掉，第二次自然稳定——幂等是「稳定在错的状态」）。

## 8. verdict 与清单

- **verdict：`needs_revision`**。两个 blocker（1.1、1.2）都在写入路径上，且都是
  「用户以为写成了、实际没写成/被改坏」这一类；修好之前不建议把工具用在真实世界上。

**实际执行过的命令清单（全部在 /tmp 的临时世界里，未动仓库）：**

- 基线六套：`python3 tests/run_tests.py`、`test_schema.py`、`test_store.py`、`test_serve.py`、
  `test_docs.py`、`classlint/tests/run_tests.py`（各 `| tail -3`）。
- 往返：`canonlint.py init/new/link` 组合（含重复跑、`--author`、特殊字符标题矩阵）。
- 审计：`canonlint.py <world>`、`classlint.py init/check`。
- Python 探针（3.14.8）：`store.parse_entry` / `iter_entry_paths` / `root_cards` /
  `_atomic_write`（SIGKILL、延迟并发）/ `yaml.safe_load` 形态矩阵；
  3.12.10 上只跑了 `pathlib.rglob` 符号链接探针（缺 PyYAML，其余工具命令跑不起来）。
- 示例世界：七棵树 python 级扫描 + 每棵树首两张卡 `link` 差分。

**亲手复现的发现（跑过、有原始输出）：** 1.1(a)(b)(c)、1.2、2.1、2.2、3.1、3.2、3.3、
L1–L5、L6、L7、L8、L9、L10、矩阵里除「大小写不敏感」外的全部格子。

**只读代码推断、未实测：** 
- `_atomic_write` 无 fsync：断电后 os.replace 的持久化顺序（ext4 auto_da_alloc 等）未验证；
- 大小写不敏感文件系统（macOS/Windows）上 `Foo.md`/`foo.md`、`entries`/`Entries` 的行为；
- Python 3.12 下 RecursionError 的触发深度可能与 3.14 不同（路径同源，机制不因版本消失）；
- `date` 裸写成 `datetime.date` 对导出/前端的传染（`serve.py`/`export` 不在本份范围，仅在此记名）。

**疑似属于其他份（一行，不展开）：** 判定层——`title:` 空值与各种 null 形态目前不被 CA101 拦下；
`date` 裸写产生的 `datetime.date` 对象是否影响 JSON 导出属于接口那一份。

**没能验证的东西（下一轮输入）：**
- 真实断电/崩溃一致性（只测了 SIGKILL）；
- 大小写不敏感文件系统；
- 大世界（数千条目）下 `collect` 全量重扫的性能与并发场景；
- classlint 是否也存在与 `new` 相同的写入命令（它今天没有 new/link，未测）。
