# classlint · 项目文书

**版本：** v0.2（2026-09-24 修订，取代 v0.1 归档版）
**定位：** 马克思主义政治经济学审计工具
**核心：** 用马克思主义政治经济学的规则，审计一个虚构世界的结构

## 一、项目定位

不是世界观 wiki，不是流量计算器，不是关系图编辑器。

作者写文本，工具建模型，模型展示结构，审计报出作者看不见的矛盾。给作者看。动态的。文本在 Git 里变，模型跟着变。

## 二、底层原则

1. **Git + Markdown 是唯一事实来源。** 文本变，模型变。模型是 Git 的投影。
2. **固定关系，实体开放。** 关系是语法，必须固定。实体是词汇，用户随便定义。
3. **三层咬合，不分主次；本体论平等，实现论有序。** 流量层是数据，生产关系层是结构，个人关系层是语境。没有数据就没有结构，没有结构数据就没有意义，没有语境结构就是干骨架。实现顺序：生产关系 → 流量 → 个人关系（见开发计划）。

## 三、三层架构

### 第一层：流量层（数据）

四种线，记录"多少、多快、往哪、够不够"：

| 线 | 记录什么 | 审计什么 |
|---|---|---|
| 物流线 | 粮食、税、贡赋 | 守恒律：流入 < 需求 → 报警 |
| 暴力线 | 驻军、行军、海防 | 补给：军队跨线无补给 → 报警 |
| 信息线 | 驿路、情报 | 时延：命令晚于政变 → 报警 |
| 人员线 | 迁徙、流放、朝圣 | 守恒：流出 > 流入且无端点 → 报警 |

### 第二层：生产关系层（结构）

七种关系，记录"谁、凭什么、向谁、为什么"：

| 关系 | 含义 |
|---|---|
| `owns` | 谁占有什么（所有/占有；区别于控制——管家控制、领主占有） |
| `controls` | 谁控制谁/什么 |
| `extracts` | 谁从谁身上拿走什么 |
| `coerces` | 谁对谁施加暴力 |
| `legitimizes` | 谁给谁合法性 |
| `owes` | 谁欠谁 |
| `depends_on` | 谁靠谁养 |

五条核心规则（PE001–PE005）：

- **PE001：** 抽取必须有基础（`controls` / `coerces` / `owns`）
- **PE002：** 不能镇压自己的供养者
- **PE003：** 合法性不得无锚闭环——`legitimizes` 图的强连通分量若没有任何来自分量外的合法性输入，报警；有外部锚点的互锁合法（依据：WGP v0.5 魔戒 dogfood，"魔戒↔索伦支配"式规范性互锁是常态，简单禁环会误伤）
- **PE004：** 剩余必须收敛，不能有黑洞（定量判定依赖流量层数据；生产关系层先行实现定性版）
- **PE005：** 劳动者必须被覆盖，不能有隐形剥削（同 PE004，定性先行）

交叉规则（PE006–PE008）：

- **PE006：** 剩余刚好够活 + 抽取在增加 → 危机积累
- **PE007：** 人口在增长 + 占有关系不变 → 结构性压力
- **PE008：** 暴力线镇压的对象，同时是物流线的供养来源 → 镇压自己的基础

### 第三层：个人关系层（语境）

为什么需要这一层：生产关系和流量数据，描述的是"阶级"和"系统"。但具体的人，处在具体的私人关系里。这些关系不直接是剥削，但它们影响生产关系的运转。

- 领主和封臣之间有联姻——地租可能被减免
- 商人和工匠之间有师徒——抽取可能被容忍
- 守港人和渔民之间有共同祭祀——镇压可能被延迟

忽略这一层，模型会变成"纯经济人"的世界。每个人只是阶级的载体，没有血肉。

五种关系字段：

| 字段 | 含义 | 例子 |
|---|---|---|
| `kin` | 亲缘 | 父子、兄弟、联姻、收养 |
| `allegiance` | 效忠 | 宣誓、庇护、主从、师徒 |
| `bond` | 情感 | 友谊、爱情、仇恨、嫉妒 |
| `affinity` | 身份 | 同乡、同门、同袍、同族 |
| `history` | 历史 | 旧债、旧仇、旧盟 |

每条关系可带强度或性质标签，不强制。

个人关系层不参与核心审计规则，但提供"修正项"：

- PE002 报"镇压自己的供养者"——若镇压者与被镇压者有 `kin: 兄弟`，报"亲情与镇压矛盾"
- PE006 报"剩余刚好够活 + 抽取在增加 → 危机积累"——若抽取者与被抽取者有 `allegiance: 庇护`，报"庇护关系可能缓冲危机"

个人关系不是装饰。它是审计的修正项。

**注：** 个人关系层的具体字段、强度、与 PE 规则的互动方式，待作品注入测试集后自然优化。当前版本仅作占位与方向声明。

## 四、展示层（三种视图）

| 视图 | 展示什么 | 关键点 |
|---|---|---|
| 关系图 | 静态结构：谁控制谁、谁抽取谁 | 节点+边，最易做 |
| 地图 | 空间结构：四种线 | 物流、暴力、信息、人员四层叠加 |
| 时间线 | 时间结构：点事件 + 结构变迁 | 世界内历史，与 Git log（世界外历史）分开 |

时间线两种节点：

- **点事件：** 瞬时。"老守港人上任""渔业崩溃"
- **结构变迁：** 区间。"封建地租→商业资本"。本质是被时间化的关系变更

**"第3版灰港设定"不进时间线。** 那是 Git log，属世界外历史。世界内历史用 `source: [[entry-id]]` 挂钩。

**反事实推演 = 时间维度上开 Git branch。** 世界树机制。

## 五、设计原则

1. **关系固定，实体开放。** 关系是语法，必须固定。实体是词汇，用户随便定义。
2. **流量层提供数据，生产关系层提供解释，个人关系层提供语境。** 三层咬合，才是完整审计。
3. **审计 = 用生产关系层的规则，查流量层的数据，用个人关系层修正，报出结构性的矛盾。**
4. **AI 可选。** 用自己的 API key，帮忙填空，不是核心。AI 产出永不自动入库，须作者确认。
5. **Git 是唯一事实来源。** 模型是 Git 的投影。

## 六、待思考的问题

1. 关系图的边，是四种线各画各的，还是叠在一起？
2. 地图的四种线，能不能互相转换？（物流断→暴力？信息断→人员？）
3. 时间线是一条轴还是两条轴？（点事件 + 结构变迁，同构还是异构？）
4. 世界内历史，是文本还是模型？它住 Git 里还是住数据库里？
5. AI 的角色是什么？提取器、提问者、检查者、连接者？
6. 个人关系层的五种字段，够不够？与 PE 规则的互动方式，待测试集验证。

## 七、修订说明（v0.1 → v0.2）

1. 生产关系由"五种"更正为**七种**：补 `owns`（PE001 的基础列表与 PE007 的"占有关系"此前引用了它但未定义）。
2. **PE003 精细化**：从"合法性不能闭环"改为"不得无锚闭环"——WGP v0.5 已用魔戒 dogfood 证明规范性互锁是常态，简单禁环与既有裁决冲突。
3. PE004/PE005 标注"定性版先行，定量判定依赖流量层数据"，消除与开发计划排期（流量层 Sprint 4 才开始）的矛盾。
4. 删除两条已被开发计划裁决的待思考项（"先写哪层"→生产关系层先；"先写哪条规则"→PE001–PE003 先）。
5. AI 条款去除 WGP 遗留术语（canon → 入库）。
6. 项目代号 Poliscan → **classlint**（POLISCAN 与 Vitronic 交通测速系统重名，SEO 不利）。
